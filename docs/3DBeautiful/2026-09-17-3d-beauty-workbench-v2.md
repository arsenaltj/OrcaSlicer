## 1. 方案定位

本方案将原“区域配色 + ImageMap 输出”思路，重构为一个**独立的 3D 美颜工作台（3D Beauty Workbench）**。

核心目标不再是服务某一条打印链路，而是构建一个：

> **基于很多小块（micro-patch）的 3D 局部编辑引擎。**

该引擎优先解决 3D 人像的局部外观优化问题，并为后续的几何美颜（瘦脸、大眼、提鼻梁、收下颌等）预留统一底座。

### 1.1 重新定义系统边界

旧方案中，区域编辑与 ImageMap 耦合较深，导致：
- 上游交互被打印策略约束；
- 首版价值不清晰，容易被后端实现牵着走；
- 很多“为打印而做”的能力并不等于“对用户有价值”的美颜能力。

新方案要求：
- **工作台独立存在**；
- **ImageMap 仅为下游可选消费者，不再是核心模块**；
- 首版只围绕“局部编辑引擎”做最小闭环；
- 未来再在同一套小块系统上叠加几何变形。

### 1.2 一句话概括

> 先把模型表面拆成很多可编辑的小块，先做局部外观编辑；后续再基于同一套小块逻辑做瘦脸、大眼等几何美颜。

## 2. 产品目标与非目标

### 2.1 首版目标

首版只做一个能真正用起来的闭环：

1. 模型表面小块化；
2. 小块可选中、可高亮；
3. 小块支持颜色 / 明暗 / 去杂色 / 平滑 / 细节保留等外观编辑；
4. 小块支持合并、拆分、组织成可理解的区域组；
5. 可对边界进行修正；
6. 支持撤销 / 重做；
7. 支持保存 / 重开恢复；
8. 输出独立于 ImageMap 的标准编辑结果。

### 2.2 首版非目标

首版明确**不做**：
- 与 ImageMap 深度绑定；
- 自动生成最终打印策略；
- 一键美颜；
- 一键瘦脸 / 一键大眼；
- 自动重塑五官；
- 复杂妆容系统；
- 大量无价值“工作台”附属功能。

## 3. 核心设计原则

### 3.1 先独立成编辑层，不绑定打印链路

输出内容不再是“给 ImageMap 的一次性结果”，而是稳定的中间资产：
- patch 数据；
- patch group 数据；
- 外观编辑参数；
- 编辑后的目标贴图；
- 未来几何变形参数（预留）。

这样后续可以：
- 接 ImageMap；
- 接其他颜色映射方案；
- 直接做 3D 预览；
- 做通用模型导出。

### 3.2 先做很多小块，再谈语义美颜

不要先强求“20 个大区域”或者“自动识别完整五官”。
真正稳定、可演进的底层应是：

> **很多小块（micro-patch）作为最小编辑单元。**

20 个区域可以作为展示层或默认分组参考，但不能作为底层设计约束。

### 3.3 先做表面外观编辑，再做几何编辑

当前阶段只处理：
- 颜色；
- 明暗；
- 饱和度；
- 去杂色；
- 平滑与细节保留；
- 边界修正。

几何编辑（瘦脸 / 大眼 / 提鼻梁）放到第二阶段，但架构要预留。

## 4. 整体架构

```text
模型生成 / 导入
   ↓
[小块生成层]
   - 模型表面切分为很多 micro-patch
   - 脸部更细，非脸部可更粗
   ↓
[外观编辑层]
   - 点选 / 框选 / 笔刷选择
   - 调色 / 提亮 / 去灰斑 / 平滑 / 保细节
   - 边界修正 / 锁定 / 撤销重做
   ↓
[组织层]
   - 多个 patch 组织成 cheek / lip / jawline 等区域组
   - 支持合并 / 拆分 / 自定义命名
   ↓
[结果资产层]
   - patch 数据
   - patch group 数据
   - appearance edit 数据
   - 编辑后的目标贴图
   - geometry edit 预留
   ↓
[下游消费者]
   - ImageMap（可选）
   - 预览渲染
   - 通用导出
   - 其他颜色映射 / 打印路线
```

## 5. 四层能力模型

### 5.1 第 1 层：小块生成层（Patch Generation）

#### 目标
把模型表面切成很多可编辑的小块，作为全部编辑能力的基础。

#### 输入
- Mesh（顶点、面）；
- UV；
- 贴图；
- 可选：人脸语义先验 / 关键点 / 多视角识别结果。

#### 输出
- patch_id；
- 三角面集合；
- 邻接关系；
- 对应 UV 范围；
- 3D 中心点 / 法线 / 面积 / 曲率；
- 语义提示（可选）；
- 置信度（可选）。

#### 切分策略建议
采用两级切分：

##### A. 通用几何小块
依据：
- 网格邻接；
- 曲率变化；
- UV 连续性；
- 法线变化；
- 面积控制。

##### B. 人脸增强小块
在脸部区域自动切得更细，优先覆盖：
- 眉毛附近；
- 眼周；
- 鼻梁 / 鼻翼；
- 嘴部；
- 脸颊与下颌线；
- 额头中心等常见美颜关注区域。

结论：**脸部细，非脸部可粗。**

### 5.2 第 2 层：外观编辑层（Appearance Editing）

这是首版真正的核心。

#### 每个 patch / group 支持的能力
- 色相调整；
- 饱和度调整；
- 明度调整；
- 对比度微调；
- 去杂色 / 去灰斑；
- 平滑强度；
- 细节保留强度；
- 锁定；
- 显示 / 隐藏；
- 恢复默认。

#### 选择方式
- 点选单块；
- 框选；
- 笔刷刷选；
- 邻接扩选；
- 相似块扩选；
- 按已有 group 直接选中。

#### 交互要求
- 悬停高亮；
- 选中后边界明显可见；
- 支持局部前后对比；
- 及时刷新贴图结果；
- 支持撤销 / 重做。

### 5.3 第 3 层：组织层（Grouping Layer）

底层是大量 patch，但用户不应直接面对几百个小块。

#### 组织层的职责
把多个 patch 聚合为用户能理解的编辑对象，例如：
- 左脸颊；
- 右脸颊；
- 上嘴唇；
- 下嘴唇；
- 鼻梁；
- 左眼周；
- 下颌线左侧。

#### 支持能力
- 自动聚合；
- 手动合并；
- 手动拆分；
- 重命名；
- 保存为自定义组；
- 组级联动编辑。

#### 原则
> **底层足够细，用户层足够直观。**

### 5.4 第 4 层：几何美颜层（Geometry Beauty Layer，预留）

该层不进入首版开发，但架构必须预留。

#### 未来支持能力
- 局部位移；
- 局部缩放；
- 软选择半径；
- 对称编辑；
- 形变平滑过渡；
- 可撤销的几何变形记录。

#### 未来可落地功能
- 瘦脸；
- 大眼；
- 鼻梁微调；
- 丰唇；
- 下颌线优化；
- 苹果肌轻微增强。

#### 与当前层的关系
未来只是在同一套 patch / group 上增加几何权重与变形算子，**不需要重做另一套美颜系统**。

## 7. UI / 交互方案

### 7.1 页面结构建议

#### 左侧：3D 模型视图
- 模型展示；
- patch / group 高亮；
- 选区可视化；
- 原始 / 编辑后切换；
- 局部对比。

#### 右侧：工作台面板
分三组：

##### A. 选区面板
- 当前选中 patch 数量；
- 所属 group；
- 合并；
- 拆分；
- 锁定；
- 保存为自定义组。

##### B. 外观编辑面板
- 颜色；
- 明度；
- 饱和度；
- 去杂色；
- 平滑；
- 细节保留。

##### C. 历史与输出
- 撤销；
- 重做；
- 恢复默认；
- 保存；
- 导出编辑结果。

### 7.2 首版关键操作流

#### 典型操作流 1：眉毛颜色修正
1. 悬停左眉区域；
2. 点击选中相关 patch / group；
3. 调低饱和度与明度，减少“浓黑感”；
4. 如边界漏选，使用笔刷补边；
5. 局部预览前后变化；
6. 保存编辑记录。

#### 典型操作流 2：嘴唇修色
1. 选中上嘴唇或整个嘴唇组；
2. 调整色相与饱和度；
3. 微调边界，避免溢出到皮肤；
4. 控制平滑强度，避免丢失唇纹；
5. 保存。

#### 典型操作流 3：脸颊局部柔化
1. 选中左脸颊 patch group；
2. 适度增加平滑和去杂色；
3. 通过细节保留参数避免脸部“糊掉”；
4. 与右脸颊分别编辑，允许不对称微调。

## 8. 与 ImageMap 的新关系

### 8.1 重新定义角色
在本方案中：

> **ImageMap 只是下游消费者，不再是工作台的核心部分。**

新关系：

```text
模型生成 / 导入
   ↓
3D 美颜工作台（核心）
   - patch 生成
   - 外观编辑
   - group 组织
   - 几何编辑预留
   ↓
输出标准化结果资产
   ↓
ImageMap / 其他渲染与导出方式（可选）
```

### 8.2 接口建议
工作台对下游只提供：
- 编辑后的目标贴图；
- 可选 patch / group 元数据；
- 编辑日志；
- 版本号与缓存键。

### 8.3 明确边界
当前阶段：
- 不要求工作台知道某个颜色最终如何由六色耗材实现；
- 不要求工作台绑定具体喷嘴 / 工具轮换；
- 不要求工作台同步承载打印工艺验证责任。

## 10. 技术路线建议

### 10.1 Patch 生成
建议先做离线 / 准离线计算，避免交互阶段频繁重建。

可行来源：
- 网格邻接；
- UV 连续区；
- 曲率分布；
- 已有人脸识别 / 五官范围结果；
- 多视角语义提示（如现有自动五官定位结果）。

### 10.2 编辑实现
优先采用**非破坏式编辑**：
- 保留原贴图；
- 编辑作为参数叠加；
- 实时合成预览贴图；
- 保存时输出完整编辑结果。

### 10.3 边界修正
优先级：
1. 扩选 / 缩选；
2. 笔刷增加 / 擦除；
3. 邻接扩展；
4. 可视化边界拖动（后补）。

首版不追求复杂的“真实纹理移动”，先保证选区准确与局部调色稳定。

### 10.4 几何编辑预留
当前就要预留：
- patch 到顶点 / 面的映射；
- soft selection 权重；
- group 的中心与法线信息；
- 对称面 / 中线关系（如果可得）。

## 11. 研发阶段划分

### Phase 1：Patch 外观编辑器（首版）

#### 目标
做成一个独立可用的小块外观编辑器。

#### 里程碑
- M1：patch 生成与缓存；
- M2：patch 选择与高亮；
- M3：外观编辑参数生效；
- M4：group 合并 / 拆分；
- M5：保存 / 重开 / 导出。

#### 验收
- 一个眉毛能被单独调浅；

- 左右脸颊可分开编辑；
- 编辑后状态可保存恢复；
- 不依赖 ImageMap 也能完整工作。

### Phase 2：局部模板与语义组织

#### 目标
让用户从“单块编辑”升级到“局部区域组编辑”。

#### 典型能力

- 提供柔肤、提亮、轻修色等局部模板；
- 支持自定义区域组。

### Phase 3：几何美颜

#### 目标
基于 patch / group 承载几何形变。

#### 第一批只做
- 瘦脸；
- 大眼；
- 下颌微调。

不建议首批做过多几何功能。

## 13. 对当前工程的重构建议

根据当前方向，应执行以下收敛：

### 13.1 保留
- 已有的人脸相关区域识别 / 五官定位能力；
- 局部颜色优化实验中可复用的区域逻辑；
- 贴图处理、预览更新、模型显示基础能力；
- 可复用的结果缓存与验证框架。

### 13.2 降级或删除
- 仅为配合某一打印路线而存在的上层交互；
- 与“用户局部编辑”无关的工作台附属功能；
- 过早绑定 ImageMap 的 UI 路线；
- 不能支撑长期价值的单样本调参页面。

### 13.3 新的评估标准
以后判断功能是否值得做，优先看：
1. 是否增强“局部编辑引擎”本身；
2. 是否能复用于未来几何美颜；
3. 是否减少用户修正成本；
4. 是否与具体打印路线解耦。

## 14. 风险与注意事项

### 14.1 Patch 过细导致复杂度过高
解决：
- 底层可以细；
- 上层必须有 group 组织与默认聚合；
- 用户不直接面对海量 patch。

### 14.2 自动组织不稳定
解决：
- 自动组织只是初稿；
- 用户始终拥有合并 / 拆分 / 重命名权；
- 不追求首版全自动完美。

### 14.3 局部平滑导致“塑料脸”
解决：
- 平滑必须与“细节保留”联动；
- 首版对参数范围做保守限制。

### 14.4 架构再次被下游绑定
解决：
- 明确工作台输出是中间资产；
- 下游只消费结果，不反向主导工作台设计。

### 14.5 过早做几何美颜
解决：
- 当前只预留，不实现；
- 先把小块编辑闭环做稳。

## 15. 给 Codex 的执行指令（可直接复制）

请将当前“3D 人像区域编辑”方案重构为一个**独立的 3D 美颜工作台**，与 ImageMap 解耦。核心目标不是服务某一种打印映射，而是构建一个**基于很多小块（micro-patch）的局部编辑引擎**。

### 任务目标
1. 以模型表面很多小块作为最小编辑单元，而不是固定 20 个大区域；
2. 首版只实现外观编辑能力，包括：
   - 小块生成；
   - 小块选中 / 高亮；

   - 调色、提亮、去杂色、平滑、细节保留；

   - 撤销 / 重做；

   - patch 数据；

   - appearance edit 数据；
   - 编辑后的贴图；
5. 架构上预留后续几何美颜能力，但首版不要实现瘦脸、大眼等功能；
6. 重新梳理当前工程中哪些代码可复用、哪些功能应删除或降级，避免继续围绕无价值的工作台功能扩展。

## 16. 最终结论

本次重构后的核心判断是：

> **不要把它做成“给 ImageMap 服务的颜色分区功能”，而要做成“一个基于很多小块的 3D 局部编辑引擎”。**

这样当前能做：
- 调肤色；
- 去灰斑；
- 局部修眉；
- 嘴唇修色；
- 脸颊柔化；
- 鼻梁提亮。

未来还能扩展到：
- 瘦脸；
- 大眼；
- 下颌优化；
- 更完整的 3D 美颜系统。

ImageMap 只是后续其中一个输出方向，而不再决定这个系统该如何设计。
