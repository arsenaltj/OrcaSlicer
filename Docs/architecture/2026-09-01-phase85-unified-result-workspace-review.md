# 阶段 85：统一结果对照与历史预览架构复核

## 结论

本阶段改动限定在独立的 AI 模型生成 GUI、3D 预览相机和本地历史元数据边界内。没有修改 OrcaSlicer 的切片管线、3MF、打印配置或 printer profile，旧历史 OBJ/JSON 仍可读取。

## 交互边界

- 原“图片确认”和“3D 预览”合并为一个“结果对照”页：左侧 3D 主视图，右侧同时显示原图和 AI 生成图。
- “历史模型”保留为独立页；加载任意历史条目后回到结果对照页，避免跨标签记忆比较。
- 检查、局部改色和质量建议继续可用，但默认折叠，并按任务顺序分组，避免改变既有能力。

## 3D 相机

- 模型加载后统一进入生成模型约定的正面视角；“摆正模型”恢复正面，“三维视角”提供倾斜检查视角。
- 正交视锥按当前视角下包围盒的 X/Y 投影自适应，不再用包围球为细长模型保留过多空白。
- 绘制与射线点选共用同一取景计算，避免视觉位置和局部改色命中位置发生偏差。

## 历史兼容与文件所有权

- 本地历史 schema 升级到 4，只新增可选 `reference_image_path` 和 `ai_image_path`；旧 schema 2/3 不要求字段存在。
- 外部原图在入库时复制到 `generated_models/downloads`，元数据仅保存生成根目录内的相对路径，避免依赖用户临时文件。
- AI 原图优先复用已下载的 raw 产物；局部改色历史继承源条目的图片路径，不重复复制共享素材。
- 删除历史时只删除属于当前任务 ID 的图片，避免误删仍被其他派生历史引用的素材。
- 旧记录缺图时保留 3D 加载能力，并在原图/AI 图卡片显示明确缺失占位。

- 真实 GUI 验证了统一三栏、正面/三维视角往返、schema 4 图片恢复和旧 schema 缺图兼容。

## 剩余边界

- 已经缺失关联图片的旧历史记录无法追溯补回原素材，只能保持 3D 可用并显示缺失说明；从 schema 4 开始的新记录会完整保留。
- 正式运行目录 DLL 当前被用户实例占用，因此本轮只做隔离完整链接和 GUI 复验，没有关闭或覆盖用户正在运行的实例。
