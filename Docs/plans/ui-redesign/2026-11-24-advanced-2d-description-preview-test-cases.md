## 1. 验证规则与前置

### 1.1 验证层次

| 标识 | 方式 | 能证明的范围 |
| --- | --- | --- |
| L | 原Session／Application／Repository／Workflow定向离线行为测试 | 业务集合、资格、修订、持久化、幂等与恢复；不证明真实窗口或供应商 |
| I | 既有Ports／客户端传输注入，检查完整载荷语义与调用次数 | 请求方向、模式、摘要、接口字段、排序、次数及失败处理；不新建mock服务 |
| W | 完整匹配版本的真实Windows Orca主窗口，独立配置和已有资产副本 | 控件操作、Tab、弹窗、状态、DPI、视觉及原流程 |
| G | 后续明确预算授权后，在真实主窗口发起真实供应商任务 | 部署服务实际接受、生成／下载及任务归属；需真实ID和输入证据 |

“+”表示所列层次都要覆盖，某个自动测试通过不能替代W／G。P0覆盖任务／费用／数据正确性与主路径，P1覆盖呈现及兼容；优先级不免除规定分支。所有必要分支满足才记通过，少分支记部分覆盖或未执行。

用户已授权实施和验收，本专项2D／YOYOClaw不限次，Tripo最多10次，按剩余预算执行G；历史不限次数的记录不自动成为新任务授权，失败的新生成POST也计数，不购买额度或隐式重试。真实生成须从主窗口经过对应输入、原确认或已确认的局部直提入口。

### 1.2 固定前置与样本

| 代号 | 定义 |
| --- | --- |
| F0 | 新建高级创作，独立datadir；记录当前Tab、组／epoch、生成调用计数及模型选项 |
| FU | 可区分的主／左／后／右原图副本，记作F／L／B／R；各有不同内容替换版，记录SHA-256和尺寸；不使用私人原件 |
| FD | 正式流程取得的1～4方向设计结果及创作副本；记录uploads、input_epoch、revision、current／visible version和SHA、pending、全局draft及已提交基线 |
| FM | 已有高级模型的组／Job／冻结图片及GLB或原支持OBJ副本；可从3D点击现有“重新生成” |
| FF | 明确失败／停止／blocked的方向及成功主图；另备ambiguous／result_pending／result_saved未决记录，不能将两类混同 |
| FO | 离线可控Ports，可延迟／乱序保存、prepare、POST、轮询、解码及发布；注入磁盘／队列错误，不在正式UI开放新入口 |
| FH | 旧高级2D无新上下文记录、旧v1四图模型快照、新v2可变快照、旧智能单图及历史关联副本 |
| FX | 副本上的缺失／损坏／超限文件、错SHA、过期计划、能力撤回及只读／工作台占用条件 |

除明确异常用例外，全局输入有效、无活动任务／未决回执、服务可用、可编辑。表中“生成次数”指新图像／模型／转换创建请求，各自独立计数；GET、保存和本地prepare不能误算为生成。

### 1.3 每条证据及判定

记录用例ID及参数分支、操作与预期／实际、源码SHA及工作树快照、EXE／DLL／资源／sidecar身份、供应商／模型、输入方向／版本／SHA、group／epoch／operation／Job／task ID、预览状态、选择前后及各类调用次数。W增加窗口与DPI、截图／录像；G保留脱敏请求元数据和产物关联，不把token、URL认证参数、base64正文或私人图片写入Git／普通日志。

“其它图不变”须比较非目标current、版本／SHA、pending、latest_attempt及全局草稿，不只看画面。取消／失败的“无调用”从本次操作前基线计数。供应商语义检查到实际Client载荷，不能止于调用了某个mock方法。
