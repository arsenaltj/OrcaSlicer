## 3. M1：高级首次四图完成自动切3D Tab

### 3.1 “首次”的定义

按当前会话内每组新创作套图计算，不是整个软件仅一次，也不是每次轮询／重新生成都触发。首次生成部分失败、后来沿原补图流程首次补齐四图，仍属于这一组的首次完整完成。

打开已有历史套图、启动后恢复历史、旧单图入口，以及已经完成过引导后的局部修改／再次生图，不新建这次引导。新建下一组套图时，下一组有自己的首次引导资格。

### 3.2 引导生命周期

1. 用户按原流程发起新组初次2D生成，经过原确认，且操作已明确受理后，Host在原Session中登记该组待完成引导；绑定当前组和有效上下文。计划确认取消、请求尚未核对、旧回调均不能直接布防已完成引导。
2. 只有当前有效快照达到3.3的条件，待完成引导才进入可消费状态；在高级页隐藏时保留会话内待消费信息。
3. 当前高级创作页可见时，消费该状态并调用原switch_stage(true)。已经手动处于3D Tab时，只消费，不重复切换或重排。
4. 先登记消费，再进入可能触发下一轮render的切换，避免重入／重复快照再次执行。
5. 切回2D后，后续轮询、历史列表刷新、窗口重绘及局部再生成不得强切。
6. 离开页面不取消已受理生成；后台完成不切智能模式、工作台或其他主页面。返回同一待引导任务时，在原显示处理完成后消费一次。
7. 显式打开其他历史、新建其他创作或关闭原Session，失效旧待引导上下文。进程重启按原历史恢复规则展示，不新增引导持久化字段。

### 3.3 完整完成条件

同时满足：

- 当前组、epoch和revision合法，快照已被原Session接收，不是历史打开产生的首次“看见四图”。
- 四个当前版本均为本地已校验、可解码的usable图片；没有asset_pending、display_error或当前／可见版本不一致。
- 本轮四图没有待生成项、活动2D操作、停止意图、未核对提交或ambiguous／result_pending／result_saved等未结结果；失败尝试的旧图不能冒充本轮成功。
- 当前草稿／上传输入与这些结果匹配。

不要用group.published或“四个usable”为唯一条件，也不要用eligibility.generate_model为唯一条件。后者还包含Tripo配置、工作台保护等额外门禁：四图完整但3D服务未配置时，仍可以切到3D Tab展示原禁用原因，不能自动绕过该门禁。

### 3.4 与原显示及刷新规则配合

保留model_tab的原页面归属。仅对本次待消费引导协调wxEVT_SHOW后的顺序，防止刚切3D又被显示事件重置2D；不顺带重做所有页面的Tab记忆策略。

复用现有刷新队列、阶段切换、左栏滚动与中央四图布局。只在实际切阶段时布局，不在轮询中反复Layout／Freeze／重建视图。切Tab不调用generate_model、不打开确认框、不导航到工作台。

## 4. M3：智能2D准备失败后使用原按钮主动新生成

### 4.1 用户操作与状态表

| 当前情况 | 原“生成3D模型”按钮 | 点击含义 |
| --- | --- | --- |
| 智能2D准备已失败，正常生成资格满足 | 可点击，名称保持原值 | 使用当前输入开始一轮新的2D准备→3D |
| 上述失败的provider_error_ambiguous为true，但已知旧任务确实停留在2D准备 | 同上，允许同图主动重发 | 新flow／新Job；不把旧请求认定为“供应商未受理” |
| 用户重新上传原图、同内容副本或另一张图，输入有效 | 按正常资格可点击 | 使用当前已同步的输入；无需靠改变内容绕开旧错误 |
| 输入无效、图片加载／同步未完成、服务或配置不可用、工作台保护未解除 | 沿原规则禁用／拒绝 | 不创建新任务 |
| 正在2D准备、3D提交／生成、下载、加载或停止 | 沿原忙碌规则 | 不重复创建任务 |
| 没有当前Job、原提交回执尚未明确，或无法确认失败属于准备阶段 | 不应用本次“准备失败”例外 | 沿原待提交恢复／核对和防重规则 |
| 已提交3D、3D结果不明、模型加载失败、已停止或其他非本次失败状态 | 沿原规则 | 不因本补丁获得无条件重新创建任务的资格 |

“正常资格”沿用输入、风格、图片有效性、GPT及3D配置、工作台保护和异步同步检查；本轮不新增外网探测。用户检查网络后点击，程序照常尝试，不要求先通过新的网络检查页面。

### 4.2 资格统一，避免按钮与提交不一致

在原业务接缝内集中定义窄资格，建议命名can_restart_failed_smart_preparation。它是从真实任务事实推导的能力，不是用户可写状态。Panel发布只读能力，Shell显示与request_generate_smart执行使用同一规则；执行时重新计算，不能直接信任旧快照。

判定至少包括：智能来源；当前明确失败Job；结构化smart_phase仍为preparation；无3D提交意图／回执、Provider任务或模型产物；没有活动操作；原输入和配置资格满足。

不能仅靠UI stage==Failed、没有Tripo任务ID或SmartGenerationFlow默认Phase::Preparation判断。编辑输入可能重置本地flow，3D提交失败也可能没有任务ID；这些情况不能把3D不明确请求误归为准备失败。必要的结构化失败来源由原Panel保留只读投影，未知值按原保护处理，不增加持久化格式。

如增加ModelGenerationUIState布尔能力，默认false，并同步same_content比较，保证仅资格变化也会通知Shell；不改变advanced／legacy消费者的默认行为。

### 4.3 新生成提交步骤

1. 点击原按钮后重新校验资格和当前输入同步；本地校验未通过时不提交，也不删除原失败记录。
2. 符合本次例外时，以这次主动点击作为新生成意图，创建新的flow_id/request_id；保留原图、当前描述、风格及生成参数。
3. 按原请求持久化／幂等规则登记新意图，沿原on_preprocess及创建接口提交新准备，不调用旧Job的retry_preparation。
4. 在发送前进入原busy和请求代次保护；双击、回车连点及重复事件只能对应这一次新生成。相同新请求的通信重放必须复用该flow，不生成另一个UUID。
5. 新Job受理后绑定新Job。保留旧Job及其图片、错误和真实任务引用，取消旧本地观察资格，按原sequence／flow／呈现代次拒绝旧回调；不向旧供应商任务补发动作。
6. 新2D结果通过原质量／输入资格后，按SmartGenerationFlow原一次性claim_geometry继续3D。失败或轮询本身不自动开始下一轮；每次明确新的生成仍需用户点击。
7. 新准备再次失败，恢复本条相同资格；用户可再次点击。尚未发送即本地拒绝时，释放本次本地忙碌，不留下伪造的“请求已提交”；已发送但新Job回执不明确时，保留新flow的原恢复规则，不将它当作已确认的准备失败继续新建。

### 4.4 保留的保护与费用语义

保留旧任务retry_preparation的ambiguous保护、3D幂等及回执保护；不修改openai_preprocessor对连接错误的分类，不将ambiguous整体改成false。

用户知道网络失败后主动再次点击，可能产生另一笔2D费用；本方案不新增确认弹窗，也不自动重发。该取舍仅适用于本次明确的准备失败新生成意图，不表示程序确认了旧请求没有受理或计费。

重启恢复原失败任务只恢复输入和展示，不自动提交。恢复到已知准备失败后，用户点击原按钮可以启动新flow；恢复尚未明确受理的提交仍复用原flow。普通页面刷新、返回创作及历史打开均不等同于用户点击。
