# ADR-0002：参考视图采用能力感知的策略路由

- 状态：Proposed
- 日期：2026-08-16
- 决策范围：模型生成域、供应商 Gateway

## 背景

阶段 50 的机器人和相机证明 Image2 四宫格能改善背面约束；阶段 51 的狐狸和塔楼又证明同一路线无法稳定覆盖复杂附件与离散重复结构。固定采用一种多视图生成方式会把图像供应商的能力和失败模式固化到正式 Sidecar。

## 决策

正式模型生成域使用供应商无关的 `ReferenceViewStrategy`，至少支持：

- `single_image`：单张已确认参考图；
- `generated_turntable`：由图像能力生成并本地拆分的前/左/后/右视图；
- `provider_multiview`：由 3D 供应商或专用能力生成一致多视图；
- `user_supplied_views`：用户提供两张或以上命名视图。

领域请求只携带命名视图、冻结的几何不变量和期望能力，不携带 Tripo endpoint、文件 token、模型名或任务字段。`ModelGenerationGateway` 根据供应商能力、对象类型、成本上限和预检结果选择或拒绝策略。策略切换必须显式记录，不允许失败后隐式创建新的付费任务。

## 方案比较

### 固定 Image2 四宫格

调用少、实现简单，但本轮人工接受率只有 2/4；对离散重复结构和复杂附件不可靠。拒绝作为正式唯一方案。

### 所有任务使用供应商原生多视图

可能提高一致性，但增加供应商锁定和额外付费，且尚无本项目对照证据。拒绝作为全局默认，保留为能力选项。

### 能力感知策略路由

实现复杂度较高，但能保留单图低成本路径，并为复杂结构选择更适合的视图来源；供应商差异封装在 Gateway。采用。

## 非功能约束

- 兼容性：不修改 3MF、打印配置或 Orca 核心模型格式。
- 成本：每次策略选择和付费任务 ID 可审计；禁止无确认的跨策略重试。
- 可恢复性：状态先落盘再调用，使用输入与产物 SHA-256 防止重复付费。
- 安全性：所有本地输入和产物必须位于任务目录或经过白名单验证的模型库目录。
- 可测试性：策略选择使用纯数据契约；供应商上传、创建、轮询均可注入替身。
- 可观测性：记录所选策略、原因、能力快照、几何不变量、人工批准/拒绝和供应商任务 ID。

## 后果

- 实验编排器继续允许验证不同策略，但不得成为 GUI 契约。
- 正式 Sidecar 接入多视图前，先抽取 `ModelGenerationGateway` 和策略选择器。
- 阶段 51 不修改 C++、3MF 或正式 Sidecar 请求格式；本 ADR 在 6 例策略对照完成前保持 Proposed。
