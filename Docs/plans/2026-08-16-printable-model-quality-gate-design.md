# 可打印 3D 模型质量门禁设计

## 目标与边界

质量门禁位于彩色 OBJ 后处理完成之后、任务标记为 `ready` 之前。它回答“该制品是否可以安全交给用户复核或 Orca”，但第一版不声称能够判断身份相似度或艺术质量。

第一版完全本地运行，不调用 Image2、Tripo 或视觉模型。它复用现有 OBJ 制品和标准库，生成可持久化、可测试、可供 GUI 消费的结构化报告。

## 三种方案

1. **仅复用现有拓扑校验**：改动最少，但只能发现网格非法，无法表达接地、组件、比例和打印风险。
2. **直接引入视觉 AI 评分**：能判断身份和语义，但费用、稳定性和多视角渲染尚未具备，不适合作为第一步。
3. **确定性结构门禁 + 可插拔视觉评分**：先建立稳定领域契约，再逐步增加视觉证据。采用此方案。

## 状态模型

- `pass`：没有硬错误，也没有需要人工确认的结构风险。
- `review`：拓扑合法，但存在弱接地、极端比例、微小脱离件、较高悬垂等启发式风险。
- `reject`：空模型、非三角面、退化面、非法索引、超出面数，以及超出下游修复能力的开放/非流形/绕序异常等确定性错误。

`review` 不自动触发新的付费生成，也不删除原始模型。它允许用户查看 3D 预览并决定导入、修复或重新生成。只有 `reject` 阻止任务进入正式 ready 状态。

## 领域模块

新增 `tools/ai/printable_model_quality.py`：

- 独立解析 OBJ 顶点、三角面和可选顶点色。
- 计算包围盒、表面积、组件面数占比、边使用、退化面和绕序。
- 计算底部接触带、水平尺寸比例、向下表面积和短边分布等打印风险指标。
- 返回稳定字典契约，并可写入 `model-quality.json`。
- 阈值集中在不可变配置对象中，避免散落在 HTTP 或 GUI 代码中。

Sidecar 只负责在制品准备完成后调用领域模块、持久化报告并根据 `status` 决定 ready/reject。现有拓扑修复继续保留，不在本阶段重写。

## 第一版指标

硬门禁：

- 顶点和三角面必须存在，索引有效且只含三角面。
- 零面积/重复顶点三角面为零。
- 边界边、三面以上共边、同向共享边必须为零；若调用方明确声明 Orca 修复能力，且异常规模不超过既有修复上限，则降为 `review` 并禁止自动切片。
- 三角面数量位于产品允许范围内。

复核指标：

- 连通部件数量、最大部件面数占比和微小部件数量。
- XYZ 尺寸、水平长宽比和高度比。
- 最低层接触点/接触三角面范围占水平包围盒比例。
- 向下三角面面积占比，用于提示潜在支撑风险。
- 极短边占比，用于提示过细或过密局部结构；不直接等价为壁厚。

## 失败与兼容策略

- 报告写入失败视为任务错误，不能静默跳过质量门禁。
- 旧任务没有 `model-quality.json` 时仍可恢复并返回空 `model_quality`；第一版不在 Sidecar 启动时同步扫描全部历史大模型，后续通过模型库的显式“重新检查”入口补算，且不修改付费任务 ID。
- 多个有效部件是合法模型，不再要求强制合并为单对象。
- 所有阈值使用归一化后的 100 mm 模型坐标；若未来改变归一化尺寸，报告必须保存实际尺寸和门禁版本。
- 视觉评分未来通过独立接口追加，不修改确定性报告字段含义。

## 验证策略

1. 用合成闭合网格覆盖 pass、review、reject。
2. 用开放面、同向绕序、退化面和微小脱离组件做回归。
3. 对阶段 45 的人像和机器人 OBJ 离线运行，要求均不被 reject。
4. 运行全部 `tools/ai` 单元测试和 `py_compile`。
5. 本阶段没有 C++ 改动时不重复构建 Orca DLL；接入 GUI 后再做 Windows Release 和正式流程验证。

- 合成模型 9 项：闭合通过、开放拒绝、可修复开放复核、同向绕序拒绝、退化面拒绝、微小组件复核、弱接地复核、面数超限拒绝、报告落盘。
- 阶段 45 人像：`pass`，478,292 面、单组件、接触跨度 0.998764、向下表面积占比 0.189491。
- 阶段 45 机器人：`review`，467,634 面、3 组件、最大组件占比 0.999983、2 个微小组件、接触跨度 0.954171；没有硬错误。
- 全部 AI Python 测试 135/135 通过，全部 `tools/ai/*.py` 语法检查与 `git diff --check` 通过。
- 本批未修改 C++，因此没有重复构建 Orca DLL；下一批在 GUI 显示 `review` 详情时执行 Windows Release 和正式流程验证。
