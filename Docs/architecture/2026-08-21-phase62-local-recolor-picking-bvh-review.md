# 阶段 62 架构复核：高面数局部改色拾取加速

日期：2026-08-21

## 结论

本阶段把局部改色的三角面拾取从逐面线性扫描改为私有 BVH 候选遍历，解决生成模型接近 100 万面上限时的点击延迟风险。加速结构完全位于模型生成独立编辑器内，不改变选区语义、网格、顶点色、OBJ、Orca 工作区或切片行为。

## 实现边界

- `VertexColorRegionEditor::initialize()` 在已有面法线、中心和接缝邻接分析之后，为三角面建立只读 BVH。
- 节点只保存轴对齐包围盒、子节点或面索引区间；叶节点最多包含 8 个三角面。
- 构建使用面中心最长轴的中位数划分，保证同中心或高度重叠的面仍能稳定、均衡地拆分。
- `pick_face()` 先按射线进入距离从近到远遍历包围盒，再对叶节点候选复用原有精确射线/三角面相交测试。
- 距离相同的重叠三角面固定选择较小面 ID，避免 BVH 遍历顺序引入不稳定结果。
- 编辑器清空或切换模型时同时释放 BVH；没有全局缓存和共享可变状态。

## 复杂度和兼容性

原拾取每次必须测试全部 `N` 个三角面。新路径的典型候选规模为 `O(log N + K)`，其中 `K` 是射线实际穿过的叶节点候选；最坏情况仍由精确相交测试保证正确性。

BVH 只缓存已有面 ID，不生成或重排 `m_mesh.indices`。颜色/法线区域扩展、重复 OBJ 接缝邻接、补选/擦除、选区快照和 OBJ 写出都保持原实现。代码使用 C++17、Eigen 现有向量类型和标准库，不增加 wxWidgets、Sidecar、Provider、3MF、profile 或 Orca 核心依赖。

## 后续

BVH 解决的是点击候选搜索，不替代未来语义分割。语义选择器仍应遵守现有“输入模型/视角/点击点，输出面 ID 位图”的适配边界，并复用当前高亮、补选、擦除和写出流程。
