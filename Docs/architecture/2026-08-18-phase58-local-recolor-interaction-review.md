# 阶段 58 架构复核：局部改色交互重设计

日期：2026-08-18

## 结论

本阶段通过，局部改色仍保持在模型生成 UI 与独立顶点色选区模块的边界内。交互重组没有修改 Orca 核心模型、切片流程、3MF、打印配置、Sidecar、Provider 或外部 AI 契约，原版演进兼容边界未扩大。

## 变更边界

- `ModelGenerationPanel`：把原来的折叠表单替换为显式编辑入口和底部停靠编辑器；管理模式按钮、范围选择、耗材色块、摘要和应用状态。
- `ModelPreview3D`：维护最多 20 次临时选区快照，提供撤销、清空与键盘纠错；仍只把面选择传给独立编辑器。
- `VertexColorRegionEditor`：新增同尺寸选择位图恢复接口。接口只操作面选择状态，不修改网格、颜色、拓扑或文件格式。
- OBJ 写出、历史元数据、模型重新加载和 Orca 导入继续复用阶段 55–56 已验证链路。

## 与 Orca 的解耦

- 没有向 `libslic3r` 的打印、切片或配置对象增加 AI 字段。
- 没有修改 3MF schema、打印机 profile 或项目配置持久化。
- 选区撤销不接入 Orca 全局撤销栈，避免局部预览临时状态污染项目历史。
- 目标色仍来自 `IPrintablePaletteProvider`；没有让 UI 直接读取或改写 Orca 全局耗材配置。
- 新控件全部位于 AI 页自己的 wxWidgets 面板，关闭功能时不会改变原版准备页或切片行为。

## 文件与数据兼容

- 原始 OBJ 不覆盖，确认应用后仍生成新的顶点色 OBJ 副本。
- `restore_selection` 要求快照尺寸与当前面数完全一致，模型切换后历史立即清空，避免跨模型恢复错误面 ID。
- 颜色写出仍使用标准 OBJ RGB 顶点色顺序；本阶段没有改变阶段 56 的通道契约。
- 本次正式验证产物保留 290,438 个三角面和 23 种实际颜色，目标为 `#00FF00`，未选区域颜色保持不变。

## 风险与后续

- 当前四个色块在约 1547×981 的正式窗口下布局清楚；若未来支持窄窗口或超过四色，应切换为可换行色板组件，而不是继续横向增加按钮。
- 当前撤销只覆盖选区变化，不覆盖已经写出的改色 OBJ；这是有意边界。已应用结果通过历史模型和保留源 OBJ 回退。
- 主构建配置仍为 `BUILD_TESTING=OFF` / `BUILD_TESTS=OFF`，新增 Catch2 快照测试源码已提交到测试目录，但当前 build 不生成测试目标。正式行为由 Release 构建和真实 GUI 旅程覆盖。
- 后续语义分割仍应按“返回面 ID/选择位图”的适配接口接入，不应把服务调用写进 `VertexColorRegionEditor`。
