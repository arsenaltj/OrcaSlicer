# 模型生成三风格：500 次社区场景质量验证

> 本报告基于 100 张来源可追溯的公开图片，对单色雕塑、多色写实和多色卡通执行共 500 次 Image2 候选生成。500 次是严格付费尝试上限，不包含任何 Tripo 调用，也没有为失败候选做隐式付费重试。

## 1. 为什么这样抽样

[MakerWorld 的公开分类](https://makerworld.com/en/3d-models/400-household?designCreateSince=0&orderBy=random&randomSeed=1703675808304)同时覆盖艺术、教育、时尚、兴趣与 DIY、家居、微缩、道具、工具、玩具与游戏，并直接提供 AI Scanner、Image to Keychain、Statue Maker 等图片到模型邻近入口。因此验证范围不能只放在人像和宠物，也必须包含实用品、机构、建筑、玩具与薄结构。MakerWorld 与 Insta360 的[相机配件设计活动](https://blog.bambulab.com/lets-make-it-bambu-lab-and-insta360-launch-luna-ultra-design-challenge-on-makerworld/)也支持把电子产品、支架和装配接口纳入测试。

Printables 的[官方社区统计](https://blog.prusa3d.com/flash-contests-two-years-anniversary_90777/)显示，实用/家居改进、节庆设计、工具与配件参与度最高；其[2025 年度奖项](https://blog.prusa3d.com/printables-awards-2025-celebrating-the-best-in-3d-printable-design_126519/)把热门模型归纳为实用/功能、玩具/游戏、装饰/艺术三组。

社区页面只用于确定用途与权重。正式源图来自许可清晰的 Wikimedia Commons 文件，避免把社区作者缩略图直接当作可复用测试资产。

## 2. 样本设计

- 100 张唯一源图，20 个细分类，每类 5 张。
- 每张源图生成 5 个候选：单色雕塑 1、多色写实暖/冷 2、多色卡通暖/冷 2。
- 总计 500 次 Image2 候选；不调用 Tripo。
- 每个候选最多一次付费请求；失败不自动付费重试，硬上限 500。
- 暖/冷两组不是额外风格，而是验证同一风格在耗材色变化下的结构与主体保真稳定性。

## 4. 源图、许可与可复现性

- 100 张源图 SHA-256 全部唯一，均通过完整解码、最小尺寸、MIME 和主体可读性检查。
- 许可分布：Public domain 24、CC0 15、CC BY 16、CC BY-SA 45。
- 不接受 ND、NC、Fair use 或未知许可。
- 每条记录保存作者、许可、原始文件页、下载地址、检索词、修改说明和必保留元素。
- 源图只做 EXIF 方向修正、等比缩放和 RGB JPEG 归一化；不把预处理编辑伪装为原图。

采集器基于 MediaWiki 的[搜索 API](https://www.mediawiki.org/wiki/API%3ASearch)和[图片信息 API](https://www.mediawiki.org/wiki/API%3AImageinfo/en)，按 Commons 的[机器可读数据说明](https://commons.wikimedia.org/wiki/Help%3AMachine-readable_data)解析许可，并保留符合 Commons [署名行规范](https://commons.wikimedia.org/wiki/Commons%3ACredit_line)所需的来源字段。每张具体文件页见 `source-manifest.json`。

## 5. 正式运行结果

### 5.1 总体指标

| 指标 | 结果 |
| --- | ---: |
| 计划候选 | 500 |
| Image2 付费尝试 | 500 |
| Tripo 调用 | 0 |
| 成功输出 | 479 / 500（95.80%） |
| 明确失败 | 19 / 500（3.80%） |
| 中断时状态不确定 | 2 / 500（0.40%） |
| 成功输出中通过自动 3D 门禁 | 463 / 479（96.66%） |
| 端到端得到自动合格 3D 输入 | 463 / 500（92.60%） |
| 成功输出自动质量均分 | 96.14 / 100 |

“成功输出”只表示 Image2 结果完整落盘；“自动合格”还要求 raw/3D-reference 的主体面积、边缘、透明度、连通性和构图通过门禁。人工主体保真问题另外记录，不会被自动分数掩盖。

### 5.2 三风格

| 风格 | 成功/计划 | 自动合格/成功 | 门禁通过率 | 均分 | 端到端自动合格率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 单色雕塑 | 93 / 100 | 87 / 93 | 93.55% | 95.66 | 87.00% |
| 多色写实 | 192 / 200 | 187 / 192 | 97.40% | 95.84 | 93.50% |
| 多色卡通 | 194 / 200 | 189 / 194 | 97.42% | 96.67 | 94.50% |

结论：卡通在这批样本上自动分最高、端到端合格率也最高；写实与卡通门禁表现接近。雕塑的内容质量并不差，但在小主体、多主体和服务失败上损失更明显。

### 5.3 暖冷色板

| 色板 | 成功/计划 | 自动合格/成功 | 均分 |
| --- | ---: | ---: | ---: |
| 暖色 | 192 / 200 | 187 / 192 | 96.41 |
| 冷色 | 194 / 200 | 189 / 194 | 96.11 |

自动统计上两套色板接近；人工目检显示暖色更稳。冷色方案中的浅色/白色区域更容易与透明或回退背景混淆，植物、毛发、白猫、白色服装和鸟类羽毛上可见空洞或碎片化。这个差异尚未被均分充分反映。

### 5.4 类别表现

- 25/25 成功且 25/25 自动合格：水生/爬行、电子产品、厨房器具、穿戴、工具/收纳、两轮/板类、道路/工程车辆、塔/地标、建筑、植物/有机。
- 25/25 成功但有门禁阻断：关节/玩具 19/25 合格，主要是明确多主体组合被连通性门禁拦截。
- 猫类最弱：23/25 成功、16/23 自动合格，问题集中在两只猫的数量/断开和浅色毛发透明化。
- 其他缺口：鸟类 22/23 合格（火烈鸟太小）、机构 23/24 合格（齿轮雕塑碎片化）、薄结构 23/24 合格（桌灯太小且多组件）。

### 5.5 16 个自动门禁阻断

- 双猫：虎斑猫冷色写实/卡通 2 个；黑白双猫五种风格全部阻断，共 7 个。
- 多主体玩具：机器人玩具组 3 个、木陀螺与配件组 3 个，共 6 个。
- 单项：火烈鸟雕塑、齿轮组雕塑、桌灯雕塑，共 3 个。

这里有两类不同含义：火烈鸟/桌灯属于真实构图风险；双猫和玩具组有一部分是“用户明确要多个主体，但门禁按单连通主体判断”的产品语义冲突，不能简单等同于生成质量差。

## 6. 稳定性发现

- 本地 Windows 偶发短时文件锁可能令原子状态替换报 WinError 5。基准工具已只为本地 JSON 写入加入有限退避重试；该重试不包围也不会重放付费调用。
- 19 个明确失败中，18 个是 `Could not connect to the preprocessing service`，1 个是 `preprocessing service rejected the request`。失败呈短时间窗聚集，随后同类素材又能成功，主要是服务/传输稳定性而不是素材不兼容。
- 2 个中断时处于 `calling` 且没有输出的候选被视为付费状态不确定，永久跳过；恢复只继续明确未调用的任务。
- 失败候选没有自动重试。正式运行因此保留了真实的 95.80% 服务成功率，也证明当前版本若要给内部同事顺畅使用，仍需要连续失败熔断、可解释状态和用户主动重试，而不是后台盲重试。
- 多个复杂主体单次耗时超过 60 秒，部分达到约 1–2 分钟后仍能成功。客户端不应使用激进短超时，也不应让假进度永久停在 94%。

明确连接失败分布：甘地写实暖色、卓别林雕塑、邓肯写实暖色、胡迪尼 3 个、三花猫雕塑、缅因猫写实暖色、德国牧羊犬雕塑、猫头鹰雕塑、鹰写实冷色、活塞发动机卡通冷色、大卫 5 个、桌椅组雕塑。甘地卡通暖色是唯一“服务拒绝”。状态不确定的是甘地卡通冷色与埃尔哈特写实暖色。

## 7. 总结图与测试建议

### 7.1 人工目检结论

表现最稳的部分：

- 人物头像：单色雕塑对身份、头部角度、发型和服饰的保持明显好；卡通版本可爱但没有普遍变成通用大眼娃娃。
- 产品、厨具、穿戴、工具：把手、开口、镜腿、表带、壶嘴、扳手活动口和电钻构型总体稳定。
- 车辆与机构：轮数、履带、铲斗、机械臂、齿轮/活塞布局整体可识别；机器人玩具组虽然被连通门禁阻断，视觉上仍很好地保留了整组数量与排布。
- 建筑、植物和薄结构：门窗、柱列、风车叶片、乐器琴颈、伞面/猫遮挡关系总体可用。

自动门禁之外仍需修的人工问题：

1. 多主体语义冲突：案例指令要求保留双猫或整组玩具，通用构图合同却要求多主体图只取一个主角。500 基线中的提示词存在内部矛盾。
2. 浅色与背景混淆：冷色方案的白色/浅色区域在植物、毛发和服装上出现透明空洞与碎片化，暖色明显更稳。
3. 3D-reference 细结构损失：公路自行车 raw 保留轮辐，但确定性色板映射后的 3D-reference 把轮内区域大面积实心化。
4. 语义漂移：Point Loma 灯塔源图被扩写成带多栋建筑、棕榈树和岛基的景观组合，自动几何门禁仍给了高分，说明现有门禁不具备源图语义相似度判断。
5. 源集标签需收紧：原计划“多层宝塔”的实际源图是寺庙牌楼；“陀螺”源图包含鞭绳和多件配件；“仙人掌”实际为盆栽蟹爪兰。结果基本跟随了图像，但测试标签会误导结论，本报告已改用实际主体名。
6. 小主体：火烈鸟与桌灯雕塑因为主体占画面过小被正确阻断，源图裁切/重构策略还可加强。

### 7.2 基线后已落代码的修复

- 多主体规则改为：用户明确要求一对、多个、整组或准确数量时，保留所有指定主体、数量、左右关系、间距、姿态和配件；只有没有明确多主体意图时才选择一个主角。
- 非透明回退背景必须与所有耗材色和主体区域明显分离，不得使用或近似任何耗材色，降低浅色主体被当背景抠除的概率。
- 人物/人像统一增加一个低矮、平底、一体连接的底座：半身像只连接现有躯干下缘且不补造腿脚，全身像通过脚、衣摆或座椅连接，多人像共享一个底座；非人物仍保持源图底座语义。
- 上述修改均已加入提示词与验证清单断言测试。

这些修复发生在 500 次基线完成后，尚未用另一轮付费 500 样本验证，因此本报告统计仍代表修复前的真实基线。

### 7.3 下一轮建议顺序

1. 先做 30–50 个免费/小规模定向回归：双猫、多主体玩具、白色毛发、浅色服装、龟背竹/盆景/兰花、公路车轮辐、灯塔景观。
2. 为远端连续连接失败加入熔断和冷却，并只提供用户可见的主动重试；不要后台无限付费重试。
3. 增加源图—生成图的语义/结构对照，至少覆盖主体数量、对象类别、关键附件和构图范围；现有单图门禁无法发现灯塔景观扩写。
4. 在多主体图进入 3D 前明确产品语义：让用户选择“整组生成”或“选择一个主体”，不要静默猜测。
5. 将冷色板回退背景和轮辐/细孔保留纳入确定性色板映射回归。

### 7.4 分页总结图

- 主对照：10 页，列为“源图 / 单色雕塑 / 写实 raw / 写实 3D ref / 卡通 raw / 卡通 3D ref”。
- 色板对照：10 页，列为“源图 / 写实暖 / 写实冷 / 卡通暖 / 卡通冷”。
- 另有 580 张按案例/风格拆分的 raw 与 3D-reference 联系表，便于逐个放大复核。
