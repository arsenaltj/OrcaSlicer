## 5. 状态、布局和业务的边界

沿用 `ModelGenerationPanel/FeatureHost` 唯一生成所有者；`WorkspaceView/Action` 和 `ModelGenerationPresentation*` 负责具名页面/只读展示资格。布局、主题、绘制不调用生成/保存/导入/切片动作。源文件准确清单在 design-map 中，拟抽的新边界只有真实第二个消费者出现时才增加。

| 用户动作 | 必须保持 / 改变 |
| --- | --- |
| 切导航/开抽屉/相机变化 | 不改输入、模型版本或任务；选中项与当前加载资产分别显示，返回焦点明确 |
| 换图/提示词/风格/2D模型 | 旧设计/3D不再可作为当前输入继续提交；旧资产保留在历史，坏输入替换不改变原内容 |
| 改3D参数 | 输入相同的2D结果保留；只失效3D资格，不自动再付费生图 |
| 美颜编辑/预览/返回 | 灰模仅显示；强度先改待预览参数，显式预览才计算候选，接受并保存形成独立版本。返回/失败不暗中接受或丢弃；几何改变即复核选区/匹配/切片，不以面数相同认定结果仍有效 |
| 配色/底座/尺寸/设备/工艺变更 | 原几何/颜色事务和切片revision失效继续生效；单色导入也明确颜色损失并保护原件 |
| 去打印 | 只打开确认页；按当前板、切片、配置身份复核；设备未配置允许本地导出，旧G-code不得冒充当前结果 |
| 提交结果未知/停止本地等待 | 不自动重建可能已计费任务/重发设备命令；按现有ID查询恢复，显示真实不确定状态 |

GL宿主、历史恢复、打印准备回调及跨模块契约继续复用；不靠重新建GL控件达到布局效果。这里保护各既有GL生命周期，包含原生配色弹窗的已有预览，不是要求整个应用只剩一个GL实例。主题只作用新UX子树，图像/模型/耗材真实色不被递归覆盖。保留普通Orca设置、快捷键、导入、撤销、保存和手动切片。

## 6. 视觉还原与验收方法
