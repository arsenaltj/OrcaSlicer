# AI 智能推荐四色设计

日期：2026-08-20

## 目标

在模型生成的图片预览之前增加一个显式、可恢复的 AI 配色步骤。AI 根据文字、参考图和所选风格推荐四个适合模型外观与多色打印的目标设计色；用户可以修改、删除或补充颜色，确认后再生成图片与 3D。目标色不绑定当前工程耗材槽，导入时仍由用户自行匹配实际耗材。

## 产品边界

- 推荐色属于模型生成任务，不写入 3MF、打印机 Profile、耗材 Profile 或 Orca 核心对象。
- 不自动读取、占用或修改耗材槽；现有“使用当前耗材”和“自定义颜色”路径保持兼容。
- AI 调用只能由“AI 推荐四色”按钮显式触发，不因输入变化、页面切换或应用重启自动调用。
- 推荐失败、返回非法颜色或颜色过近时不覆盖现有色板，用户可以重试或回到手动设置。
- 本功能不增加智能切片、材料推荐、支撑或打印参数决策。

## 交互

色板来源增加“AI 推荐配色”。用户输入文字、参考图或两者，并选择风格后点击“AI 推荐四色”。请求期间显示可取消的进度；成功后显示四个候选色，每个候选包含 `#RRGGBB`、中文名称、语义用途和简短理由。

候选色进入“待确认”状态。用户可以点击色块替换、删除颜色或补充颜色，总数保持 1–4。修改后保留原用途说明并标记为用户调整。只有点击“确认使用此配色”后，图片预览按钮才会使用这组颜色。文字、参考图或风格改变后，已确认色板保留但标为过期，用户可以重新推荐或再次确认继续使用。

## 架构与状态机

推荐与后续图片预处理复用同一个模型任务，避免单独的 GUI 缓存和重启后重复付费：

```text
idle
  -> recommending_palette
  -> awaiting_palette_confirmation
  -> preprocessing
  -> awaiting_confirmation
  -> queued/running
  -> ready
```

C++ 只认识供应商无关的 `PaletteRecommendation` DTO。Sidecar 新增文字与图片推荐入口，创建并持久化 Job；Provider 返回结构化 JSON 后，Sidecar 校验恰好四个唯一 `#RRGGBB`、角色完整性与最小 Lab 距离。用户确认时，C++ 把最终 1–4 色及角色提交到同一任务的 `confirm-palette` 动作，Sidecar 随后复用现有文字或图片预处理函数。

`job.json` 保存候选色、摘要、确认状态、输入和参考图片路径。`latest` 恢复范围包含推荐中与待确认状态。旧任务没有这些字段时按默认空值加载，任务 schema 版本保持兼容。

## Provider 契约

Provider 输入包含用户描述、风格、打印目标，以及可选参考图。输出只允许一个 JSON 对象：

```json
{
  "summary": "温暖主体配合深色结构和高对比点缀",
  "colors": [
    {"hex":"#D96B43","name":"陶土橙","role":"primary","usage":"主体服装","reason":"大面积暖色形成视觉中心"},
    {"hex":"#3A2925","name":"深棕","role":"structure","usage":"头发与结构边界","reason":"提供稳定轮廓"},
    {"hex":"#F2D7B5","name":"暖白","role":"light","usage":"面部与高光区域","reason":"与主体色保持清晰区分"},
    {"hex":"#2F6B5F","name":"墨绿","role":"accent","usage":"配件与底座点缀","reason":"形成冷暖对比"}
  ]
}
```

角色固定为 `primary / structure / light / accent`，每个角色只出现一次。Sidecar 不信任 Provider 输出：限制 JSON 大小和文字长度、规范化颜色、拒绝重复色和低对比方案，并使用现有 `assign_palette_roles` 复核角色与颜色。

## 错误与费用控制

- 调用前 GUI 明确提示这是一次可能计费的 AI 分析。
- Provider 异常、无效 JSON、非法图片或校验失败使任务进入可解释的失败状态；不自动重试。
- `confirm-palette` 只允许作用于 `awaiting_palette_confirmation`，重复确认返回状态冲突，不重复启动预处理。
- 用户停止推荐时复用现有停止与删除路径；已完成候选可随任务恢复。
- 输入变化后不在后台调用 Provider，仅在 GUI 标记候选过期。

## 验证

- Provider 单测覆盖文字、图片、JSON 围栏、重复角色、非法 HEX、低对比和超长文字。
- Sidecar 契约测试覆盖文字/图片推荐、持久化恢复、确认后继续预处理、非法状态、停止和旧任务兼容。
- C++ 客户端解析覆盖缺失可选字段与合法推荐 DTO。
- GUI 验证覆盖显式调用、候选展示、修改/删除/补充、确认、输入变化过期、恢复与失败回退。
