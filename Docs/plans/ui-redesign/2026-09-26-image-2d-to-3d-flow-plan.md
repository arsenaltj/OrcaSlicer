# 图像页 2D 设计图与 3D 生成交互修改方案

日期：2026-09-26

状态：已按串行任务清单完成所有已授权实现与本地验收；真实付费服务和用户视觉签收待完成

串行任务清单：[图像页 2D 到 3D 流程阶段任务清单](2026-09-26-image-2d-to-3d-flow-tasks.md)

## 1. 目标与依据

在 Orca 主窗口的新图像页中，接入现有的图片生成、设计图确认和 3D 生成流程。整体 UI 重构方向保持不变：新界面负责输入、状态展示和命令入口，按钮点击直接转交现有业务流程处理；生成请求、费用确认、服务商规则、任务恢复、历史资产及导入行为继续由现有实现负责。本轮同时完成新 Shell 中的 3D 进度、失败恢复、结果预览和导入入口，不以按钮跳转或占位页代替真实结果流程。

本方案基于 `codex/team/integration` 的 `222fbc0b741996810d4d21f51e9a1b5706cc2e4f` 和用户在本轮确认的需求。实施前仍须重新核对实际工作树和相关文件。

- 用户已确认：生成中防止重复点击；2D 与 3D 的确认、失败恢复和历史行为沿用旧流程。“重新开始”置于 3D 主按钮下方，返回 2D 输入阶段，保留图片、描述、风格和模型设置，不自动发起请求，已生成设计图保留在历史资产中。

## 2. 当前代码边界

| 位置 | 已有能力或限制 | 本轮方案中的角色 |
| --- | --- | --- |
| `src/slic3r/GUI/Redesign/RedesignShell.*` | 已有本地图片校验、选择/拖入/移除、描述输入、三项风格、原图预览和 AI 服务状态；2D 按钮禁用且无事件绑定 | 新 UI 视图、状态呈现和用户输入 |
| `src/slic3r/GUI/ModelGenerationPanel.*` | `on_preprocess`、`on_generate`、`on_discard`、服务商设置、有效性校验、轮询、恢复、取消、历史、付费确认均在面板内部 | **本轮唯一业务流程实现**；现有处理函数及其状态推进保持权威，不抽取或重写状态机 |
| `src/slic3r/GUI/AI/ModelGeneration/ModelGenerationFeatureHost.*` | 持有旧生成面板，仅公开窗口、服务状态和关闭接口 | 在确有需要时承载最小 UI 桥接接口，不接管业务决策 |
| `src/slic3r/GUI/AIModelGenerationClient.*` | 已有 `preprocess_image`、`generate`、`update_generation_options`、状态查询及下载 | 只通过现有工作流所有者使用，不由新视图直接重复编排 |
| `src/slic3r/GUI/MainFrame.cpp` | 新 Shell 激活后不返回旧 Notebook；新 Shell 的 3D 模型页当前仍为占位 host | 为现有 3D 业务状态提供新 Shell 中的真实可见承载页 |
| `ModelGenerationPresentation` 及历史读取 | 校验图片和读取仅有设计图的持久记录 | 沿用原文件/真实任务 ID，不伪造或覆盖历史 |

`ModelGenerationPanel` 及其现有处理函数继续作为单一业务流程实现；`RedesignShell` 是新的呈现和命令界面。两者之间只增加实现接入所必需的窄接口：把新界面输入同步给现有流程、调用与旧按钮相同的现有动作、把现有流程的状态/图片/进度通知给新界面。桥接层不得自行做有效性判断、构造请求、弹出另一套确认、决定服务商规则、轮询任务、写历史或导入模型。

当前 `ModelGenerationPanel` 只有在 `IsShownOnScreen()` 后才执行 `build_page()`。实施时可对初始化时机或 host 持有方式做最小调整，使现有处理链能由新界面合法调用；不得依赖对不可见旧控件的程序化点击，也不得因此抽取新的共享会话或重写状态机。旧 UI 保持为现有业务流程的兼容呈现，现有处理函数仍拥有行为。若最小接入无法满足这一边界，先记录具体阻碍及拟改行为，再向用户确认。

## 4. 状态与用户动作

新 UI 只渲染现有业务流程对外提供的状态，不能仅凭“图片控件已经显示”推断远端任务已完成。一次 2D 请求继续使用旧流程记录的提交输入和真实任务 ID；晚到回调、重复提交和输入变更仍由现有处理链按原规则处理，新界面不另设一套判断。

| 状态 | 可见内容与按钮 | 业务动作 |
| --- | --- | --- |
| 无图/图片校验中/校验失败 | 现有空态、加载态、错误态；生成按钮不可用 | 本地操作，不调用图片服务 |
| 图片已就绪、服务可用 | 显示上传缩略图与原图；“生成 2D 设计图”可点击 | 沿用旧预处理前的输入校验及额度确认；确认前不提交请求 |
| 2D 请求已提交/轮询中 | 原图持续显示，右图为生成中占位；提交入口立即锁定，可见旧流程允许的停止操作 | 使用同一任务 ID 查询；重复点击与迟到回调不能重复提交或串图 |
| 2D 成功且图片已下载可解码 | 显示实际设计图；提供“生成 3D 模型”和“重新开始”；显示旧流程的质量提醒 | 仅业务确认状态允许生成 3D；下载失败不冒充成功；设计图及输入进入真实历史 |
| 2D 失败、服务断开或结果不明确 | 原图和输入保留；结果槽显示错误与重试/恢复入口 | 保留旧流程不自动重复付费调用、按任务 ID 恢复的语义；不凭超时自动创建新任务 |
| 已完成后修改输入 | 保留旧设计图历史，当前候选标记过期；主按钮回到生成 2D | 不再用旧结果启动 3D；服务商选项变更按旧 `update_generation_options` 规则处理，不误判为需重新生成图片 |
| 点击“重新开始” | 回 2D 输入/原图状态；图片、描述、风格、模型选项原值保留；3D 按钮消失 | 点击本身不发请求；先确认旧设计图已持久化，再切断当前候选与显示状态，不删除历史文件或真实任务 ID |
| 点击“生成 3D 模型” | 先显示旧确认与费用摘要，确认后转到新 Shell 可见的 3D 进度/结果承载页 | 沿用旧服务商参数校验、单次提交、恢复、下载、预览、导入和普通 Orca 保护行为 |

导航离开再返回、窗口重启、恢复历史设计时，应由相同任务和输入快照恢复正确状态；不能只保留一张本地图片控件的临时状态。生成期间不应因切页取消远端任务，除非用户明确执行旧流程的停止动作；停止本地等待与远端可能继续计费的提示保持原语义。

## 5. 实施顺序与所有权

1. **固定现有行为基线。** 定位新按钮分别对应的旧入口及完整调用链，记录 `on_preprocess`、`on_generate`、`on_discard`、服务商选项联动、确认、停止/恢复、历史和导入的当前行为。优先复用已有测试；新增测试只覆盖桥接后可能出现的重复提交、状态同步和输入保留风险，不调用真实付费服务。
2. **增加最小 UI 桥接。** 在 `ModelGenerationPanel`/`ModelGenerationFeatureHost` 的现有所有权下，按实际代码需要暴露窄的意图与状态接口。接口只允许三类操作：同步图片、描述、风格和 3D 选项；触发现有的预处理、3D 生成、停止/恢复、历史打开和导入动作；订阅现有流程产生的阶段、进度、错误、图片及模型状态。公开入口内部直接进入旧按钮使用的现有处理链，不复制处理函数内容，也不新增业务状态机。
3. **处理现有流程的初始化。** 针对 `build_page()` 依赖可见状态的问题，只调整保证既有处理链可初始化所需的生命周期或 host 接线。初始化调整不得改变默认参数、请求时机、确认顺序、恢复规则和旧界面行为；不得把不可见旧按钮当作命令 API。
4. **连接新图像页。** 将 `RedesignShell` 的图片、描述和三项风格通过桥接同步给现有流程；2D 按钮触发旧 `on_preprocess` 对应动作。根据现有流程通知显示服务状态、生成中、停止/重试、结果图片和按钮可用性；2D 结果显示顺序继续沿用旧 `apply_preview_stage`，新界面不自行选择另一份输出。
5. **连接服务商及 3D 设置。** 在新左栏呈现 `Tripo`、`腾讯混元3D` 及旧流程已有的目标面数、几何、纹理和输出格式。控件值通过桥接进入现有 `GenerationOptions`/`update_generation_options` 路径；联动、默认值、费用摘要、校验和保存结果均取自旧实现。生成 3D 按钮进入旧 `on_generate` 对应动作及原确认链。
6. **实现保留输入的重新开始。** 新界面将当前呈现阶段切回 2D 输入阶段，保留已同步的图片、描述、风格、服务商、质量和格式设置，不发起服务调用。现有设计图与真实任务记录仍由旧历史逻辑保存；若需要调用旧清理入口，只能使用不会删除持久资产且不会改变业务语义的现有分支。
7. **完成本轮 3D 页面及历史入口。** 在新 Shell 中呈现现有业务流程的 3D 提交进度、停止、失败恢复、下载、模型预览和导入入口；所有动作继续转发现有处理链。默认收起的“我的图片”面板读取并打开现有历史记录。外层布局和控件采用本方案的深色视觉，进入新 Shell 后不跳往空白页或旧 Notebook。
8. **按范围验证与交付。** 构建当前 checkout 对应的应用及受影响测试目标，检查最新源码、配置、DLL/EXE/sidecar 身份；完成受影响的真实主窗口可见状态和交互检查。用户承担的视觉验收项目单列为待反馈，未通过前不宣称视觉完成。

`ModelGenerationPanel` 的现有处理链是业务所有者，桥接层和 `RedesignShell` 不能取代它。任何阶段如发现必须更改请求载荷、状态转换、持久化格式、服务商或费用规则、确认顺序、停止/恢复、历史、导入行为，先停止该项实施并向用户说明具体差异和影响，得到确认后才能修改。

## 6. 验证清单

- **UI 逻辑测试：** 服务未连接/图片空或不合法时禁用；双击只提交一次；描述/风格变更令 3D 候选过期；服务商变化联动有效选项但不误触发 2D；重新开始保留所有输入且不发请求；历史设计图可重新打开并恢复输入；晚到回调不覆盖新一轮状态。
- **旧业务回归：** 两服务商默认值、30/100/200 万面规则、Tripo 几何/纹理/OBJ 费用摘要、混元受限选项、2D/3D 确认取消、超时/断线恢复、任务状态查询、设计图历史和 3D 导入。旧路径继续可用。
- **离线隔离：** 针对相关 `tools/ai/test_*.py`、`tests/slic3rutils` 中的 UI/图片测试添加或选择有意义的用例；检查提供商调用确实被 mock，不能以测试文件名判断隔离。
- **实际窗口：** 对照两个 Figma 画板检查上传成功、双大图布局、生成中占位、完成图、长文案、滚动设置栏、固定按钮、风格/服务商菜单、深色确认弹窗、键盘焦点和 100%/125% DPI；检查切页、返回、重新开始、展开图库和历史恢复。测试真实付费生成只在具体调用授权及预算内执行；未执行的路径明确标为未验证。
- **源码/产物：** 记录 HEAD 与相关修改哈希、实际构建配置、测试日志及候选二进制/资源身份；检查 diff 不含服务端协议、凭据、预设、项目格式和无关资源更改。

## 7. 方案复核：已发现的漏洞及处理

1. **旧流程存在界面初始化依赖。** `ModelGenerationPanel` 延迟至可见才初始化，直接从新界面调用可能遇到控件或状态尚未建立。对策是增加最小生命周期/host 接线，使同一现有处理链可被新命令入口调用，并用旧界面回归证明行为未变；不通过模拟点击隐藏控件解决。
2. **3D 页当前为空。** 单接按钮会形成确认后无可见结果的断链。本轮必须同时完成进度、失败恢复、预览和导入入口，全部读取或触发现有业务流程；在这些状态有真实承载前不能将流程标记为接通。
3. **重新开始可能误删仅有设计图的任务。** 旧 `reset(true)` 会检查持久资产再决定是否调用 `remove`；本轮“重新开始”只复位新界面的呈现阶段并保留输入，不能直接调用会删除任务或目录的分支，也不能在新界面另写一套历史判断。若现有公开入口无法在不改业务语义的前提下保留资产，实施前须提交具体差异让用户确认。
4. **静态图无法说明生成结果。** Figma 左右两图使用同一示例资源，实际实现须显示用户原图和服务返回图，并将缺失/下载失败视为失败状态。
5. **新增设置挤占左栏。** 固定底部操作区、滚动上部设置区；窄窗口和 DPI 放大时不遮挡费用摘要或次按钮。各控件统一深色视觉，不能让默认白色原生下拉/弹层破坏整体风格。
6. **服务商变更与输入变更不同。** 旧流程支持更新生成选项；不能将所有字段变化一概视为需要再付费生成 2D。反之图片/描述/风格变化不能沿用旧设计图提交 3D。
7. **高级旧能力明确延后。** 可打印配色、AI 推荐色和图片处理高级参数不迁入本轮新图像页，留待后续设计与实现。本轮不得为补齐这些控件而更改默认值或现有旧界面行为，也不能放置无效入口。
8. **历史入口也是占位能力。** 新 Shell 的 `Assets` 页不能代替已实现的历史列表；默认收起的“我的图片”面板至少要能使用真实历史记录重新打开设计，否则“保留历史”的承诺无法由主窗口检验。
9. **双向同步可能回流成重复动作。** 现有流程更新状态、恢复历史或切换服务商时会反向更新新 UI；这些程序性更新不得再次被解释为用户提交。桥接接口应区分“同步显示值”和“用户意图”，并对事件重入、页面销毁后的迟到回调及重复订阅做定向测试。

## 8. 已确认范围与实施约束

1. **业务复用方式：** 新界面的按钮、选项和状态展示接入现有 `ModelGenerationPanel` 业务处理链。允许为接线增加窄接口和必要的初始化调整；不抽取共享会话、不重写流程、不复制请求编排，也不让新 Shell 直接调用 client 绕过旧规则。
2. **本轮 3D 范围：** 包含新 Shell 中的生成进度、停止和失败恢复、3D 结果预览及导入入口，并沿用旧流程对应行为。
3. **本轮设置范围：** 包含 `Tripo`、`腾讯混元3D` 及旧流程已有的服务商相关质量、面数、几何、纹理和输出格式设置；保留新界面的三项风格。
4. **后续范围：** 可打印配色、AI 推荐色和图片处理高级参数本轮暂不迁入，后续有实际设计和需求时再实施。
5. **变更确认门槛：** UI 接线和视觉重构可按本方案实施；一旦实现需要改变请求载荷、业务状态、付费确认、服务商规则、持久化、取消/恢复、历史或导入语义，必须先向用户说明并确认，不得以 UI 重构名义顺带修改。

本文件只记录拟议改动和风险复核，不表示业务代码改动、真实付费调用或主窗口验收已执行。
