# 3D 模型质量复核界面设计

## 目标

让用户在 3D 预览阶段直接知道模型是“检查通过”“建议复核”还是“不可继续”，并能对旧模型补做本地检查。质量状态属于当前预览模型，不属于输入表单，因此页面切换或从模型库重新载入后必须保持一致。

## 方案比较

1. 弹窗：醒目，但会打断生成旅程，也不利于用户一边旋转模型一边核对问题。
2. 底部状态栏：实现简单，但只能显示一句话，容易和下载、导入、切片状态混淆。
3. 3D 预览旁常驻质量卡：结论稳定可见，详细指标可按需展开。采用此方案。

## 页面行为

- `pass`：绿色“结构检查通过”，显示面数、组件、接地和悬垂摘要，导入正常可用。
- `review`：橙色“建议复核”，显示中文风险，例如微小脱离件、弱接地、潜在支撑或可交给 Orca 修复的小缺陷；允许导入，但不把它描述成完全通过。
- `reject`：红色“未通过结构检查”，列出硬错误并禁用导入。
- 无报告：灰色“尚未检查”。新任务等待 Sidecar 返回；历史模型提供“重新检查”按钮。

质量卡默认只展示结论和最多两条建议，详细指标放在可折叠区域，避免再次让生成页面拥挤。

## 接口与安全边界

新增 `POST /v1/orcaslicer/model-jobs/{job_id}/recheck`。接口不接受文件路径，优先分析任务已经登记且位于任务目录内的 OBJ 制品；对早期没有任务清单的模型，只允许按已校验 UUID 接管 `generated_models/<UUID>/model-vertex-color.obj`，并验证真实路径仍位于该目录内。因此 GUI 无法借此读取任意本地文件。

Sidecar 将报告写回任务目录的 `model-quality.json`，返回现有 job 契约。重新检查完全本地运行，不创建 Image2、Tripo、conversion 或下载任务。

C++ `JobStatus` 只解析稳定字段：状态、错误/警告代码、面数、组件数、最大组件占比、接地跨度、向下表面积比例和修复能力。未知代码使用通用中文提示，保持前后端向后兼容。

## 历史模型

模型库元数据继续保存 `job_id`。双击历史条目后：

- 先显示已有质量状态；
- 缺少报告时显示“尚未检查”；
- 用户点击“重新检查”后用当前条目的 `job_id` 调用窄接口；
- Sidecar 无该任务或原制品已不存在时保持模型预览，不删除历史记录，只显示无法重验。

GUI 和 Sidecar 必须由启动脚本显式共享同一个 `ORCASLICER_AI_OUTPUT_DIR`。不能用进程当前目录作为产品级契约，因为 Orca 启动和文件操作过程中可能改变当前目录。

## 验证

1. Python：recheck 路由、无任务、非 ready、制品缺失、pass/review/reject 和不触发付费调用。
2. C++：JSON 解析与未知字段兼容。
3. Windows Release：客户端与生成页面定点编译、GUI 静态库和 DLL 链接。
4. 正式 Orca：加载人像显示通过；加载机器人显示复核；重新检查不创建付费任务；reject 时导入禁用。
