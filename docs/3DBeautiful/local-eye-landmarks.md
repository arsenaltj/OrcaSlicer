# 工作台五官轮廓（Windows 内部试用）

2026-09-18：原始贴图多视角 RetinaFace / FaRL 继续提供人物归属及语义证据。可选 MediaPipe Face Landmarker 的 478 点检测现在用于眼睑、虹膜、上下嘴唇和口腔开口轮廓，不再要求 FaRL 先完整识别出眼区。鼻子、眉毛等沿用 FaRL；本轮没有用硬轮廓替代鼻子的柔和结构，也没有实现骨相变形。

`local_face_landmarks.py` 将各视角关键点通过可见三角面及重心坐标还原到现有网格，舍弃 MediaPipe 预测深度。轮廓对应点的三维偏差按眼距归一化，至少两个独立视角一致才融合。同方向的原图和裁图只计一个视角；可见但不属于区域的表面也贡献反对票，不能靠简单取并集扩张。虹膜使用椭圆并裁入眼睑范围。闭眼、太小、遮挡或定位冲突时不强行创建新轮廓。

粗视角及面部裁图之后，最多为两张已确认的大脸增加各三个 768 像素局部视角（正向及左右 25°），不额外运行 FaRL。这些相机从脸部表面法线和范围推导；沿用原生 Z 向上的搜索约定，任意倒置、大幅倾斜和多人模型尚未验证。当前实现检查已知表面的多视角一致性，还不是原始照片的未知相机配准或三维人脸模板拟合。

这是五官形状提示，不是新增瞳孔像素语义类别，也不会提升原 FaRL 的置信度。它不能代替骨相网格、眼球几何或遮挡重建。实际颜色仍按三角面存储，显示曲线不能消除粗网格的物理台阶。

## 本地运行依赖

沿用显式 `local_semantic_runtime.json` 的 CPU 环境。若该环境安装 `mediapipe==1.0.1` 且 `weights_directory` 含以下固定模型，则启用五官提示；普通运行不安装依赖、不下载模型、不上传输入。缺少或不兼容的扩展回退到既有识别。

- [MediaPipe Python 包](https://pypi.org/project/mediapipe/1.0.1/)，Apache-2.0。此次 Windows x64 wheel SHA256：`96dc9de6bd04a6315ef424fda5c48e0929f2d78317295e75bc32c0bceeab517b`。
- [官方 Face Landmarker 模型](https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/latest/face_landmarker.task)，本地文件名 `face_landmarker.task`，大小 3,758,596 字节，固定 SHA256：`64184e229b263107bc2b804c6625db1341ff2bb731874b0bcc2fe6544e0bc9ff`。下载地址含 latest，不能仅凭地址接受后续不同内容。
- [官方使用说明](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker/python)。本轮仅验证 CPU 静态图像模式。

扩展包版本、模型哈希以及两个 landmark 模块均进入运行/策略指纹；策略升级为 `visible-face-semantic-v3-shape-consensus`。主程序和 Python 侧同步固定模块清单，旧推理缓存不能冒充新结果。证据中的可选 `feature_details` 与旧 `eye_details` 分开：前者允许同一人物面部上的形状修正，后者仍严格限制在 FaRL 整眼区内。原生端验证模型哈希、有序网格对应、无歧义面、人物锚点、至少两个视角、不跨人物/头发及不重叠；虹膜必须是眼睑区域的子集。形状提示不改写原始语义置信度、已知面计数或打印耗材契约。

## 交互与保存

2026-09-19：修复整块五官内部没有 FaRL 种子时，可靠多视角轮廓也被拒绝的问题。新策略 `visible-face-semantic-v4-surface-context` 允许单个形状使用 2–4 条独立终点的局部表面路径建立人物归属；每条最多跨 8 条共享网格边，终点必须是同一人物已确认的面部。路径必须处于至少两个一致视角都可见的脸部范围，不能越过已确认的头发、脖子或另一人物；开口和非流形边不用于搜索。路径只是上下文，绝不加入五官着色范围。

证据新增可选 `anchor_paths`，Python 和原生端均校验范围、数量、唯一终点、人物归属与逐段共享边；原生校验使用已证明对应的本机网格，不能靠附近空间坐标或工作进程自报连接。旧的内部锚点证据仍有效。没有降低模型分数或多视角一致性要求，没有增加相机或新模型依赖；旧已保存编辑继续直接恢复。路径长度目前受网格边数限制，在网格密度差异大的模型上仍需验证。

新建分区使用通过一致性检查的眼唇轮廓，先退回旧的同类语义种子，再应用新范围，支持缩小和扩大。已保存的手工区域保留：先“更多操作 → 更新五官识别（保留当前区域）”，再按需“补出五官区域并配色（可撤销）”或“按识别结果修整眼珠（可撤销）”。补区域保留范围外配色，不等于用新的自动结果覆盖整份手工作品。选中眼珠后点“放大编辑这块”，中心点移动，左右/上下控制点调整宽高。已确认眼珠的控制点使用平滑椭圆，并受眼睑范围约束；局部边界自由拖动仍可用于人工修正。

原生编辑辅助在新旧轮廓及一圈邻面内清理微小断片：连通片最多 8 面、少于本标签面数的 5%，且至少 60% 边界邻接同一允许标签才替换。区域外、主要连通片、整块小五官和其他人物保持。虹膜单独在眼睑内做同样的孔洞/孤岛处理。它只整理自动编辑种子，不改原始语义证据，也不代表全模型碎区已经解决；不均匀网格上的效果仍需更多样本。

最终区域沿用现有 puzzle 保存格式；识别标签、眼部范围和虹膜保存在 `orca.beauty-guidance/v2`，绑定原始贴图及几何。有效旧记录直接恢复，不因算法升级抹去用户修改。撤销、草稿和另存新版本沿用原路径，运行时检测器不写进模型文件。

当前机器的隔离依赖及证据位于 `.tmp/dev/eye-landmarks/`，配置只改变本 checkout 的 `.tmp/dev/data`。既有历史模型和原识别环境未覆盖；这些本机路径不是其他机器的安装契约。
