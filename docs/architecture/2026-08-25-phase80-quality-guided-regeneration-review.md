# 阶段 80：质量引导的下一次生成优化验收

日期：2026-08-25

## 结论

阶段 80 已把现有最终模型结构检查和 AI 视觉复核结果整理为稳定、可读、可直接复用的下一次生成建议。用户可以在质量卡中查看建议，并通过“应用到下一次生成”把建议追加到文字描述；该操作完全在本地执行，不会自动提交 Image2、Tripo 或其他 Provider 请求。

这一步建立了“生成结果 → 质量证据 → 用户确认的下一轮输入”闭环，但不自动修改网格、不自动重试生成，也不绕过既有付费确认流程。

## 质量建议契约

- 新增纯标准库模块 `model_refinement.py`，根据既有 `model-quality.json` 和 `visual-quality.json` 生成 schema 1 的可选 `refinement` 对象。
- 建议只消费白名单问题代码，并按拓扑、连接、厚度、底座、悬垂、细节、语义、颜色的稳定优先级去重，最多返回 6 类问题。
- 摘要、标题、单项说明和 prompt 后缀都有 UTF-8 字节上限；未知、异常、已通过或不可用报告安全忽略。
- Sidecar 只在读取公共任务状态时即时派生建议，不增加路由、持久化字段或任务迁移。
- C++ 客户端把建议视为可选 DTO：只接受 schema 1、白名单代码和有界字符串；错误或未来版本建议不会影响旧任务恢复。

## GUI 行为与安全边界

- 质量卡新增“下一次生成优化”区块，显示摘要和前三类问题，完整 prompt 后缀保留在 DTO 中。
- “应用到下一次生成”只调用本地文本控件 `ChangeValue`，不调用 `AIModelGenerationClient` 的任何网络方法。
- 总输入继续受 2000 UTF-8 字节限制；后缀已存在时按钮禁用，避免重复追加。
- 应用后当前模型和质量报告继续保留用于对比；因为输入发生变化，既有 stale-input 保护仍要求用户重新生成后才能导入新结果。
- Image2 和 Tripo 的既有预处理、付费生成与确认流程未修改。
