# 多视图模型生成设计

## 目标

解决单张正面参考图无法约束背面和侧面的主要质量缺口，同时把 Tripo 3D 生成控制在小批量范围内。第一轮只比较阶段 49 中问题最明显的机器人和相机；最多新增 2 次多视图 3D 生成，只有方案有效但仍需验证角色细连接时才使用第 3 次狐狸样本。

## 方案比较

### A. Image2 四视图板 + Tripo 原生多视图建模（采用）

Image2 基于已经确认的严格四色参考图，生成固定 2×2 布局的前、左、后、右四视图。本地切分、重新执行四色门禁，并用视觉模型确认四个视图属于同一对象、朝向和布局正确。通过后分别上传四张图，调用一次 Tripo `multiview-to-model`。

优点是每个模型只消耗一次 Tripo 3D 生成，Image2 可在进 3D 前充分重试；缺点是四视图板可能出现身份漂移或布局错位，因此必须有一致性门禁。

### B. Tripo image-to-multiview + multiview-to-model

视图一致性由同一供应商保证，但每个样本需要额外一个 Tripo 多视图任务。保留为 Image2 无法生成稳定视图时的备选，不作为第一轮默认。

### C. 四视图拼图直接送单图接口

实现最简单，但供应商可能把四个面板理解为四个对象或把分隔区域建成几何体，不采用。

## 数据流

1. 读取阶段 49 已冻结的 `model_reference.png`、提示词、风格和动态四色色板。
2. Image2 只改变观察角度，不重新设计主体，输出无文字、无分隔线的 2×2 四视图板。
3. 按固定象限切出 `front / left / back / right`。
4. 每张视图独立通过透明背景与严格四色处理；任一视图图片门禁失败则阻止 Tripo。
5. AI 一致性复核检查身份、比例、配色、配件、视图顺序和缺失/重复视图。
6. 通过后上传四张模型参考图，由 Tripo 适配器创建一次多视图 3D 任务。
7. 复用既有 OBJ 转换、纹理烘焙、顶点色、拓扑、五视图和视觉复核链路。
8. 与阶段 49 单视图基线逐项比较背面异常、视觉得分、结构状态和人工评分。

## 状态与防重复

- 每个样本使用独立 `multiview-state.json`，记录清单指纹、Image2 调用、四视图哈希、视觉门禁、Tripo 任务 ID、转换 ID 和最终制品。
- Image2 调用开始前记账；调用失败且没有落盘图片时拒绝自动重试，必须显式指定人工重试。
- Tripo 返回任务 ID 后立即落盘，再做图片副本和其他非关键文件操作。
- 一致性复核为 `review` 时优先继续使用 Image2；若人工确认只是方向命名或不可见表面等软性疑问，必须持久化批准理由、图片哈希和 AI 警告后才可创建 Tripo 任务。
- 已有 Tripo ID 时只能恢复原任务，不得重新生成。

## 架构边界

- 多视图参考属于模型生成领域制品，不属于 Orca GUI 状态。
- `tripo_client` 只负责供应商协议映射和网络安全校验。
- 实验编排器负责付费状态、对照实验和报告，不进入正式 Sidecar API。
- OBJ 后处理、结构门禁和视觉复核继续复用供应商无关模块。
- 方案验证成功后，正式接入应扩展模型生成 Gateway 的 `reference_views` 能力，而不是让 GUI 认识 Tripo endpoint 或 file token。

## 验收

- 无付费确认参数时不会创建 Image2 或 Tripo 任务。
- 四视图布局、尺寸、色板、一致性和恢复逻辑有单元测试。
- 机器人、相机最多各一次 Tripo 多视图 3D 生成。
- 最终 OBJ 仍满足动态四色和拓扑门禁。
- 至少一个样本的背面/侧面语义或视觉分数明显优于单视图基线，否则不进入正式产品链路。
- 阶段结束输出 ADR 与架构复核，检查 Orca/Sidecar/供应商依赖方向。
