# 产品需求文档｜OrcaSlicer AI 3D Printing UX

版本：产品展示与测试基线，2026-09-28。代码观察范围为集成分支 `19a0b7f05e96c304b0a1e333a61d67643cb2e21b`；`6pro` 交接稿和 Figma 为需求来源。本文中的状态是**这份代码基线的证据分级**，不是总体开发完成率，也不代替运行验收。

## 1 产品定位

让普通用户从一个想法或一张图片，快速完成AI创作并进入真实3D打印流程。产品把 AI 设计、模型生成与 OrcaSlicer 原生打印能力接在同一作品上下文中，让用户在每个关键步骤知道“现在看到什么、下一步会发生什么、能否返回”。

用户价值不是增加 AI 按钮，而是降低建模与材料选择门槛，同时保留 Orca 的工程、预设和手动切片能力。设备打印是独立、明确确认的动作。

## 2 用户问题

| 问题 | 用户可感知的后果 | 产品回应 |
|---|---|---|
| 建模门槛高 | 有照片或想法却做不出可检查的 3D 作品 | 分阶段确认 2D 设计和真实 3D 模型 |
| “生成成功”不等于满意 | 正面像、侧面或局部不对，重来成本高 | 对比来源、保存版本、局部可选编辑与返回路径 |
| 屏幕颜色和耗材混淆 | 以为预览颜色必然等于实体成品 | 分开原始外观、目标外观、机器材料近似与实物结果 |
| 切片参数复杂 | 不清楚为何选某方案、修改后结果是否过期 | 以原生 Prepare/Preview 为真值，候选显式应用与撤销 |
| 失败后难恢复 | 网络中断、保存失败或历史切换导致重复付费/丢稿 | 保留输入/原件、按同任务恢复、明确失效原因 |

## 3 产品目标

1. **AI 工作流：** 当前作品从输入到原生准备连续，步骤与版本可追溯。
2. **易用性：** 普通路径先给结果和清楚的主动作；高级参数按需展开。
3. **生成准确方便：** 分别评价 2D 意图、3D 造型、可打印几何，不能用“文件下载成功”代替准确性。
4. **多色匹配：** 基于实际物理耗材与工艺能力给可解释的近似，保留关键区域的人工决定。
5. **3D 美颜：** 在真实模型上做可预览、可回退、可保存的局部外观优化；不强制每个用户进入编辑。

阶段目标是软件内可继续、可恢复的作品与有效切片；设备启动、监控和成品评价必须由真实设备与实物证据补齐。未经标定，不承诺屏幕与实物一致。

## 4 用户角色

以下为产品设计假设，尚未由正式用户研究验证。

| 角色 | 核心任务 | 优先保障 |
|---|---|---|
| 首次创作用户 | 上传照片或描述想法，得到愿意打印的模型 | 输入清楚、费用知情、设计确认、错误可恢复 |
| 有模型的打印用户 | 跳过 AI 生成，处理已有 OBJ/GLB/3MF | 本地路径、原件保护、原生配置与切片 |
| 再次制作用户 | 找回旧作品，更换材料或只改局部 | 版本身份、目标色保留、过期结果重算 |
| 测试与制作人员 | 判断软件与实体结果是否达到预期 | 可定位的任务、版本、配置、切片和实物记录 |

## 5 核心场景

1. **照片生成作品：** 图片/文字 → AI 设计 → 用户确认 → 3D 生成 → 可选美颜 → 材料匹配 → Prepare → 智能/手动切片 → 打印确认 → 保存资产。
2. **已有模型打印：** 打开本地模型或 3MF，直接检查模型、材料和准备条件；AI 服务关闭时仍保留普通 Orca 路径。
3. **历史作品再次编辑：** 选择正确历史版本，局部修改或换耗材，只重做受影响的匹配、准备和切片步骤。

各阶段的用户动作、系统反馈和测试关注点见 [User Journey](User-Journey.md)。

## 6 用户流程

```text
图片或文字 → 2D设计确认 → 3D模型生成 → 可选3D美颜 → 颜色匹配
                                        ↓
                                  Orca Prepare → Smart Slicing/手动切片
                                                      ↓
                                             有效预览/G-code → 打印确认
                                                      ↓
                                                作业与作品记录
```

- **不满意：** 2D 不符时改输入/风格并保留旧设计；3D 不符时返回设计或选择历史版本；材料近似不满意时改目标/耗材，不隐式重写模型。
- **失败：** 远端提交响应不明先查同一任务；编辑/保存失败保留原件和草稿；候选或 G-code 过期则重新校验/切片；设备状态未知时不显示“打印成功”。
- **捷径：** 已有模型从 3D/Prepare 开始；有效历史工程从当前版本继续，不要求重新购买生成。

## 7 功能需求

状态定义：**[已实现]**＝集成分支有可定位的实现，范围限于表述的能力；**[部分实现]**＝有模块或局部路径，但完整旅程、格式组合或 GUI/硬件验收不足；**[规划]**＝设计目标或建议，不能由现有源码确认可用。逐项证据见 [Requirements Evidence](Requirements-Evidence.md)。

| ID / 状态 | 用户需求与产品规则 |
|---|---|
| F01 **[部分实现]** 输入与导航 | 支持图片/文字创作、已有模型和历史入口；当前作品、版本与阶段应持续可见。三种图片入口、首次配置后置和统一新导航尚未核验。 |
| F02 **[已实现]** 付费 3D 确认 | 在提交前说明本次任务、服务与本地停止边界；文本与已确认设计有分支。中断后查询同一任务，不因响应未知自动重复付费。此项只确认提交链代码。 |
| F03 **[部分实现]** 2D 确认与生成准确性 | 预览与确认基础可见；设计版本、跨页面失效提示和真实供应商/多输入端到端仍需验证。2D 成功不得称已生成可打印模型。 |
| F04 **[部分实现]** 模型与历史资产 | 展示、加载和保存历史的路径存在；原件、候选、已保存派生版须可区分。旧资产、多格式和跨进程恢复需组合验收。 |
| F05 **[部分实现]** 3D 美颜 | `BeautyWorkbenchControls` 已接入预览、对比、保存、撤销/草稿等路径；不满意可返回。复杂边界、迟到识别与全部格式保存仍未完成验收；美颜应可跳过。 |
| F06 **[部分实现]** 颜色匹配 | 颜色意图、物理通道、局部匹配和应用门控有代码；目标外观与机器分配必须分开。recipe 字段存在不代表所有方案可应用，实物色差待标定。 |
| F07 **[已实现]** 原生准备边界 | 生成产物交给 Orca 适配器；Orca 管尺寸、摆放、预设、3MF 与 Prepare。导入不应静默切片或改预设。不同格式/历史路径仍按 F04/F06 补验。 |
| F08 **[部分实现]** 智能切片 | 候选、比较、revision 校验、显式应用/撤销及原生正式切片结构存在。候选指标、新鲜度与真实 GUI 流程须按当前工程组合验证。 |
| F09 **[部分实现]** 打印与监控 | 原生 Monitor/Printer 页面存在；具体设备连接、启动确认、命令归属、终态与实物完成不能由页面存在推断。 |
| F10 **[规划]** 新 UX 全程状态 | 完整新界面的空白、进度、费用、无网、未知、失效、保存失败及辅助可读状态需按 Figma 与产品规则补齐。Figma 按钮不计实现。 |
| F11 **[规划]** 实物颜色保障 | 目标色到真实耗材/工艺的校准和稳定色差结论依赖材料、设备与成品测试；不得从屏幕预览或配方结构推断。 |
| F12 **[规划]** 可量化成功指标 | 建议分别记录输入到可检查 3D、首次可编辑、有效切片、任务恢复及打印认可率；当前无统一用户研究基线。 |

所有阶段保留原生手动路径。未确认设备能力时只能展示可用的准备/导出动作，不能承诺自动启动或远程监控。

## 8 状态设计

| 对象 | 必须区分的状态 | 失效/返回原则 |
|---|---|---|
| 创作输入与 2D 设计 | 草稿、生成中、可确认、已确认、旧版、失败 | 修改输入不删除旧设计；明确选择继续旧版或重新生成 |
| 3D 生成任务 | 未提交、已提交、查询中、完成、失败、结果未知 | 结果未知先按任务 ID 查询；本地停止不等于远端取消/免单 |
| 模型与美颜 | 原件、编辑草稿、预览候选、保存派生版 | 切换作品先处理未保存更改；迟到 AI 建议不得覆盖人工编辑 |
| 颜色 | 原始外观、目标外观、材料近似、不可执行 | 换材料/工艺后重新检查锁定和槽位；未分配不能假接受 |
| Orca 工程与切片 | 当前模型/配置 revision、候选、已应用、切片中、有效、过期 | 几何、尺寸、配置或耗材变化后重新判断 G-code 新鲜度 |
| 设备作业 | 未发送、待确认、执行中、停止、失败、完成、未知 | 设备完成与用户认可成品分别记录；未知不显示成功 |

## 9 异常处理

| 异常 | 期望反馈与恢复 |
|---|---|
| 图片损坏、格式/大小不支持、服务不可用 | 不清空旧输入；说明本地校验与外部服务限制，给出本地模型/普通 Orca 退路。 |
| 生成响应中断、重复点击 | 保留任务身份并查同一任务；不要在不确定时自动提交新付费任务。 |
| 3D 预览或美颜保存失败 | 原件和已保存版本不变；草稿/错误可定位，用户可重试或放弃候选。 |
| 识别结果晚于人工修改 | 显示建议与当前草稿差异；不得自动覆盖用户选择。 |
| 耗材缺失、锁定失效、recipe 不可执行 | 标出受影响区域与材料条件，阻断应用；允许改目标或选择可执行方案。 |
| 项目变化、切片过期、正式切片失败 | 解释哪项输入变化，保留未受影响的版本，重新准备或切片后再继续。 |
| 设备不可达、发送结果未知或摄像头失败 | 把连接/视频/作业状态分开；确认当前设备及作业后才允许重试命令。 |

## 10 验收标准

测试采用固定作品、模型、材料/机型配置及源版本，逐项记录输入、预期、实际和证据。离线单测、GUI、设备与实物评价分层，不互相替代。

1. **创作 J1：** 识别输入及费用，2D 不满意返回；确认的设计版本进入 3D。断线后恢复同一任务，不重复提交。未确认 2D 时不把预览当模型。
2. **已有模型 J2：** AI 关闭/离线仍能走本地导入和 Orca 手动准备/切片；原文件不变，3MF/预设语义保留；支持范围外的格式明确失败。
3. **历史 J3：** 正确选择原件/派生版；局部编辑可撤销、失败不覆盖原件；换材料只重算受影响的匹配与切片，不复用过期 G-code。
4. **颜色：** 1–6 物理通道、未分配、锁色失效、无可执行配方分别有真实结果；屏幕预览、模型区域和实物色差单独报告。
5. **切片：** 候选比较使用当前 revision；显式应用后原生正式切片，工程变更使旧结果失效；撤销恢复原配置。
6. **设备：** 使用指定设备核对启动前确认、状态时间戳、停止/失败/完成归属。未接硬件时只报告“未验证”，不称端到端打印成功。
7. **可用性：** 窄窗口/DPI、键盘、中文路径和长任务反馈在对应版本可见；完成一次跨页面返回和失败恢复试验。

## 11 当前能力

集成分支快照中可见：`ModelGenerationPanel` 图像/文字任务与付费确认、`GeneratedModelArtifact` 不可变交接、`BeautyWorkbenchControls` 工作台接线、`ColorIntent` 1–6 物理通道契约、`LocalPrintColorPanel` 条件应用、Orca `Prepare`/`Monitor` 页面、`SmartSlicingCoordinator` revision 校验与应用/撤销路径。有关源码锚点及相应测试文件列在 [Requirements Evidence](Requirements-Evidence.md)。

`6pro` 交接稿引用的是较新的模型生成分支 `a6d3743…`，其中部分 GUI 与性能结果未包含在本集成快照；本文不把它们计为集成验收。本次仅做静态文档核对，没有在此工作树运行应用、付费服务、打印机或成品评价。

## 12 后续规划

按既有主计划与负责分支核对实际差异，再由产品/测试决定放行范围：优先补全三条用户旅程的可见状态与失败恢复；随后处理跨格式保存、材料匹配与切片新鲜度的组合验收；最后用真实设备、材料与成品建立颜色和打印反馈。几何修整、配方扩展及完整 UX 改版须按现有计划和实际能力单独评审。

这不是新增开发任务台账。集成分支的 [开发状态](../../coordination/current-development.md)、负责分支的有效主计划、对应提交和测试证据共同决定实际进度；较新主计划尚未同步到此集成快照时，不用本文代替它。
