# 生成模型“导入到工作台”按钮回归风险评估

## 现象

安装包中模型生成并完成 3D 预览后，结果页右侧的“导入到工作台/打开工作台”入口可能消失。模型文件和预览已经存在，但用户无法继续进入准备页。

## 根因

页面按钮由 `RedesignShell` 根据 `ModelGenerationUIState.can_import` 创建；该字段直接取 `ModelGenerationPanel::m_import->IsEnabled()`。原判断同时要求：

- 生成任务仍与当前输入、当前打印机耗材色板完全一致（`!stale_job`）；
- 远端服务可用，或当前下载路径仍被识别为有效本地模型；
- 任务状态仍为 `ready`。

打印机耗材同步、色卡切换或用户调整输入后，`stale_job` 会变为真。即使已生成的模型已经下载并成功显示，旧条件仍把导入控件禁用；`RedesignShell` 随后将页面动作设为 `None`，所以表现为按钮消失。这个状态把“需要重新生成”错误地当成了“已有模型不能导入”。

安装目录模型路径问题是同一版本中的另一项风险：旧包曾把侧车输出指向可执行文件旁的 `models`，安装到 `Program Files` 后普通用户不可写。该问题会导致下载/历史恢复失败，但不是本次按钮状态机的直接原因。当前修复继续使用用户数据目录，并保留显式 `ORCASLICER_AI_OUTPUT_DIR` 覆盖。

## 修复范围

新增纯逻辑判定，将两个状态分离：

- 已加载且路径有效的本地模型，即使输入或当前色板已变化，仍显示并允许导入该确定的模型；后续导入设置仍可重新匹配耗材。
- 尚未加载预览时，只有任务处于可重新加载状态才显示重载入口。
- 下载/预览忙、没有模型文件、或路径不可用时仍禁用入口。
- `stale_job` 仍继续阻止重新生成，不改变生成请求、耗材配置、工作台保存和撤销流程。

## 风险评估

| 风险 | 级别 | 控制措施 |
| --- | --- | --- |
| 用户在修改输入后导入旧模型 | 低 | 只放行已经加载的本地模型；页面状态和摘要仍保留“输入/颜色已变化”的提示，重新生成路径不受影响。 |
| 下载尚未完成时误导入 | 低 | 未加载预览时仍要求 `model_ready` 且下载未启动，忙状态继续隐藏/禁用入口。 |
| 服务不可用导致历史模型无法导入 | 低 | 已加载模型以本地路径为准；路径丢失时不放行，避免伪造可用状态。 |
| 资产目录迁移改变历史模型位置 | 中 | 输出目录继续由用户数据目录承载；迁移保留旧文件，安装目录不作为默认写入位置。 |
| 外部 API、模型格式或 3MF 兼容性 | 低 | 本次只改内部 UI 能力判定，不修改 HTTP 契约、模型格式、导入事务或历史字段。 |
| 页面动作与面板按钮状态不一致 | 低 | `RedesignShell` 仍读取同一个 `m_import->IsEnabled()`，并增加纯逻辑回归覆盖。 |

## 验证矩阵

- 已加载模型 + 当前色板变化：入口显示且可用。
- 预览未加载 + 可重载任务：显示重载入口。
- 预览未加载 + 下载进行中：入口不可用。
- 缺少本地模型文件：入口不可用。
- 忙状态、候选修复、耗材/模型保存流程：保持原有阻止规则。
- 定向单元测试覆盖上述状态组合；Windows Release 安装包另行执行内容检查。

## 未完成的验收

本地逻辑和构建验证不能替代同事电脑上的真实 GUI 验收。仍需在安装到 `Program Files` 的标准用户环境中确认：生成模型完成、切换打印机耗材/色卡后按钮仍显示；服务断开时已下载模型仍可导入；历史模型和 3MF 读取正常。设备同步、视觉接受和实物打印色准不属于本次按钮修复的证明范围。
