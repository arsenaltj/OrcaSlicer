# 阶段 77：已批准四色候选真实模型验证设计

日期：2026-08-23

## 目标

把阶段 64 的四色预览基准与真实 Tripo 模型验证安全连接起来。只有本地门禁通过、视觉报告已完成、人工决定为批准，并且批准记录仍绑定当前严格预览与视觉报告 SHA-256 的单个案例，才允许创建或恢复一次付费 Tripo 任务。

生成完成后立即用阶段 76 的 `structural-v9` 检查最终 OBJ，输出目标色表面积覆盖、结构风险和可打印性证据，不把 Provider 成功等同于质量通过。

## 方案

新增独立工具 `tools/ai/approved_palette_model_validation.py`，不把实验编排塞进 Sidecar 或 GUI。

执行顺序：

1. 加载冻结清单与逐案例状态，只接受一个案例。
2. 重新验证本地门禁、视觉报告、人工批准及全部绑定哈希。
3. 验证建模参考图和目标四色，写入不含密钥的预检审计记录。
4. 未提供显式付费确认时只完成预检，不创建远程任务。
5. 提供确认后复用 `run_paid_tripo_validation` 的任务 ID 先落盘与可恢复流程，创建或恢复单个 Tripo 任务。
6. 对最终顶点色 OBJ 运行 `analyze_printable_obj(..., target_palette=palette)`，保存 v9 报告和汇总。

## 安全与恢复

- 不允许工具自己创建人工批准；批准仍由阶段 64 的 `manual-review` 命令生成。
- 预览、视觉报告或建模参考图任一哈希变化后，旧批准立即失效。
- 付费确认只授权指定案例的一个可恢复任务；已有 `validation-state.json` 时恢复原任务，不重复创建。
- API Key、Provider 响应正文和用户配置不写入仓库。
- 最终质量 `review` 保留制品供复核，`reject` 不宣称通过。

## 边界

- 新代码、测试和文档仅位于模型生成域。
- 不修改 MainFrame、Plater、CMake、3MF、profile、打印参数或 Orca 默认行为。
- 不调用或复制智能切片业务。
- 生成输出仍位于被忽略的 `generated_models/`。
