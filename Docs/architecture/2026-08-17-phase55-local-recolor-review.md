# 阶段 55 架构复核：3D 预览局部智能改色

## 结论

第一版局部改色保持在模型生成模块边界内，没有修改 Orca 的切片算法、打印配置、3MF 格式或项目兼容逻辑。选区算法、GUI 交互和 Orca 工作区导入仍是三个独立职责，可在不阻塞智能切片同事的情况下继续演进。

## 边界

- `VertexColorRegionEditor` 只依赖网格、顶点色和文件路径，负责三角面邻接、射线拾取、选区与 OBJ 副本写出；不依赖 wxWidgets、AI Provider、Sidecar 或 Orca 工作区。
- `ModelPreview3D` 负责把屏幕点击转换为模型射线、显示青色选区覆盖层，并保留原有拖动旋转和滚轮缩放。
- `ModelGenerationPanel` 只编排中文控件、当前耗材色、历史模型元数据和现有导入链路。
- 改色结果通过现有 OBJ 顶点色契约进入 Orca；不新增模型格式，不更改对象、分组、材质、UV 或三角面拓扑。

## 兼容性

- 原始 OBJ 永不覆盖；写出失败会回滚内存颜色，新副本先写临时文件再原子替换。
- OBJ 写出仅重写 `v` 行，其他 `o`、`g`、`usemtl`、`vt`、`vn` 和 `f` 行按原文保留。
- 目标色只来自现有最多四种打印耗材色，不写回或篡改 Orca 项目耗材配置。
- 若源模型本来是自然颜色，局部改色只把选区写成指定耗材色，未选区域仍保留原顶点色，历史条目继续标识为自然颜色；只有源模型已经受四色约束时，改色副本才继续标识为四色模型。
- 功能仅在 3D 生成页面且有可编辑 OBJ 时出现，不影响关闭功能或普通 Orca 工作流。

## 可演进点

- 当前自动区域识别采用连通性、顶点色差和法线连续性，适合已有色块和几何边界明确的模型。
- 后续语义分割可实现为“输入模型/视角/点击点，输出面 ID 集合”的独立选择器，再复用现有高亮、补选、擦除和写出流程。
- 若后续需要自动拆件，应作为独立的几何处理阶段，不应混入本选区模块；拆件会改变拓扑和 Orca 导入语义，需要单独质量门禁。

## 已知限制

- 射线拾取当前每次点击线性扫描三角面；真实约 29 万面模型可交互使用。若未来稳定支持百万面级频繁涂选，可增加只属于编辑器内部的 BVH，不改变 UI 契约。
- 共享边界顶点会同时影响相邻三角面显示，这是顶点色格式的固有限制；需要硬边时应由上游模型在颜色边界拆分顶点。
- 正式运行必须由启动器为 GUI 和 Sidecar 设置相同的 `ORCASLICER_AI_OUTPUT_DIR`，不能依赖 Orca 运行中会变化的当前目录。
