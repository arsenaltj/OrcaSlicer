# 阶段 85：统一结果对照与历史预览设计

## 目标与界面结构

模型生成页的结果区改为一个连续的“结果对照”工作台，不再让用户在“图片确认”和“3D 预览”之间来回切换记忆。工作台顶部横向排列 3D 主卡和图片对照区：3D 模型占较大比例，右侧图片画布同时显示原图与 AI 生成图。没有用户原图的文字生成任务仍保留原图位置并显示“文字生成，无原图”，避免布局跳变。图片处理阶段、缩放和技术指标仍可从“查看处理过程”进入，但不抢占首屏。

结果对照下方只保留一个简短质量结论。局部改色、结构检查、AI 视觉复核和下一次生成优化统一放入默认收起的“检查与编辑”区，内部按任务分组并使用更短的逐步文案。历史模型作为同一结果区的第二个标签保留，用于浏览和删除；点击加载后立即返回“结果对照”，三类素材在一个界面中恢复。

## 3D 视角

OBJ 加载后继续使用现有包围盒中心和正交投影，避免改变拾取、局部改色和结构高亮坐标契约。默认视角改为生成模型的规范正面，并把缩放重置与正面旋转合并为“摆正模型”；另保留“三维视角”用于恢复略带俯视的默认观察角。这样用户不需要拖动两百万面模型寻找精确正面，同时仍能旋转检查侧面和底座。

所有视角操作只修改预览相机，不改 OBJ 顶点、坐标系或导入姿态。模型加载、历史恢复和局部改色重新载入都走同一相机初始化，保证行为一致。

## 历史数据与兼容

历史元数据在现有 schema 上增加可选的 `reference_image_path` 和 `ai_image_path`。用户选择的原图若位于生成目录之外，在模型入库时复制到 `generated_models/downloads` 下以任务 ID 命名的稳定文件；AI 原图优先复用已下载的 raw preview，缺失时回退到现有 `preview_path`。所有持久化路径仍相对生成根目录保存。

读取旧记录时字段缺失不报错：3D 继续加载，对应图片卡显示“该历史记录未保存此图片”。局部改色产生的新历史模型继承源模型的两类图片路径，删除历史条目时同时删除仅属于该条目的归档图片；共享或旧路径不做盲删。历史加载失败时保持当前结果不变并显示原因。

## 验证

代码级验证覆盖 JSON 可选字段解析、外部原图归档、旧 schema 回退和局部改色继承。GUI 验证覆盖图片生成完成、3D 就绪、历史加载、旧历史缺图、摆正后继续旋转/缩放、展开高级工具和窄窗口滚动。最后执行 `git diff --check`、相关测试及 Windows Release 定向构建，不调用 Image2 或 Tripo。
