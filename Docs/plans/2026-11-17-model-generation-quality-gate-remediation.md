## 1. 审批范围与产品规则

| 范围 | 实施后的规则 |
| --- | --- |
| 智能模式：生成3D模型／重新生成等入口 | 每次有效操作冻结当前图片、文字、风格及模型配置，创建新的flow／request／job，重新执行本轮2D准备→3D；即使输入没变，也不复用上一次生成任务 |
| 高级模式：生成3D模型／重新生成等入口 | 每次以当前已确认四图创建新的model-plan／request／job；保持四图确认步骤，点击3D按钮不隐式重画四图 |

| 资产与历史 | 用户原图、已有设计图、高级套图和已完成模型继续保留、查看、进入工作台；本地重新加载已完成模型预览仍可用，不能借此恢复供应商任务 |

“有效操作”指当前无冲突中的生成／停止收尾，且输入满足真实文件与业务契约条件的操作。进行中按钮禁用；双击、同一次请求的网络重传不是两次新操作。

本地停止成功表示本软件不再推进该流程、下载／安装旧结果或自动提交下一阶段；不承诺供应商已经取消云端推理或退款。每次新的生成操作可能产生新的供应商调用与费用，沿既有确认／授权流程执行。

## 3. 软件修改方案

### 3.1 沿既有状态所有者简化流程

生成业务继续由智能Panel／SmartGenerationFlow、高级AdvancedCreationSession／FeatureHost及Python任务Application／Workflow拥有；Shell、HTTP、共享预览和粒子只适配输入、命令和快照。不新增第二套会话管理器或跨模块业务状态。

用户可见状态只保留：可生成→生成中→成功／失败；生成中→停止中→可生成并提示停止成功。生成中的内部2D、3D、下载、预览阶段沿现有流程；停止后的页面不提供“恢复当前任务／恢复上次任务／恢复原3D任务”。

### 3.2 每次生成使用最新输入与新身份

1. 在动作入口先取得并同步当前控件草稿和模型选项，再冻结本次输入；不先用旧任务快照回填控件。后台保存／旧任务PUT回执也不得覆盖用户较新的草稿。
2. 智能每次建立新flow、提交请求及job，完成本轮图像准备后只向3D推进一次；不按输入是否相同进入恢复、重试旧job或复用上一轮智能设计图的分支。
3. 高级保留当前组和四图资产，每次新建model-plan及job；输入与四图是否匹配仍由Session和原确认契约判定。新建3D不沿旧model-link执行resume。
4. 同一次操作继续使用现有请求身份、序列和幂等接缝：请求重传／查询受理结果只对应这一操作。下一次主动生成换新身份；取消的是跨次恢复，不是防重复。
5. 生成、停止收尾期间禁用冲突操作；当前任务的查询失败只按原查询退避处理，不能自动切换成创建新生成。当前操作尚未决时，不允许第二次提交绕过幂等。
6. 保留防过期检查，明确区分合法草稿更新与旧任务回调。不能通过删除Route／输入绑定／代次校验解决旧快照覆盖。

### 3.3 停止收尾与迟到结果

1. 用户点击停止，立即使本轮自动派发3D和结果安装意图失效，进入“正在停止…”；保留找到原操作所需的临时request／job身份，调用既有停止接缝。
2. 2D准备结束与自动提交3D之间、创建请求受理前、3D排队／运行、下载和本地模型加载各阶段均处理停止。停止早于受理回执时，迟到job只进入停止／终止收尾，不能重新绑定页面或继续3D。
3. HTTP返回`stopping`仅表示已受理停止。以应用层确认本地已终止、不会继续自动派发且旧结果无法安装为成功条件；失败／超时不显示成功，保留停止收尾资格，允许再次停止，不提供恢复旧生成。收尾确认前不放行冲突的新生成。
4. 收尾完成后清理活动任务绑定、跨次pending恢复意图、恢复索引和恢复按钮投影，保留当前用户草稿和资产，提示“已停止生成”。后续点击生成按3.2新建。
5. 后到的受理、状态、图片缓存、粒子、下载、模型解析和首帧回调均核对原操作身份／取消／代次，不能覆盖新任务或再次进入工作台。停止与完成竞争由已有应用层终态顺序裁定：已经提交的完成资产保留，已生效的停止不被晚到成功反转。
6. 保留最小诊断和取消收尾信息，用于解释失败和处理迟到回执；不形成可恢复检查点。不要用删除整个job目录、全部model-link或高级组来代替停止。

### 3.4 旧数据、启动与资产兼容

- 智能启动查询、历史打开、高级重开组和model-link观察不再选择旧未完成生成作为可恢复会话；应用重启后也不复活旧任务。当前未停止会话的普通切页返回继续显示当前任务，与旧记录恢复区分。
- Python停止／恢复筛选和仓储投影同步调整。旧文件中的状态和task引用可保留作诊断；没有新字段的旧记录按新规则安全读取，不要求批量删除／改写用户数据，不自动新增生成。
- 高级已终止／明确放弃的旧操作退出`_require_resolved`对新model-plan的恢复门禁；当前操作仍在创建或受理未明时保留防重复。必要的旧回执核对只用于终止收尾，不继续旧工作流，也不要求用户先恢复旧任务才能新建。
- 已完成模型与高级四图仍保持原历史引用和打开入口。本地预览失败后的“重新加载预览”只读既有资产，不能混用供应商恢复命令。
- 高级2D编辑、补图、草稿自动保存、四图确认和其受理核对继续沿原契约；此次不整体删除共用pending收据处理，也不复活已退役的专属生成流程。
- 共用resume接口先核对其他消费者。本轮撤除两种AI创作模式的旧3D恢复链和恢复资格，不因改需求直接破坏其他仍使用的API兼容性。

### 3.5 内容质量只作建议

复查全部`model_input_eligible`、`generation_input_quality`和`palette_quality_ok`消费者，从生成按钮、智能自动提交和阶段投影中移除内容硬门禁。保留原质量报告、测量和诊断，旧`false`也不解释为不能建模；不篡改历史报告为通过。

人物、手办、宠物、动物、建筑、产品、多人、贴边、满幅浮雕、浅色、有效纯色或大量透明图均采用同一规则：满足实际文件／接口和当前输入契约即可提交。质量评估缺失、异常或超时按无可用建议处理；粒子提取失败仅继续Logo，不等待动画准备后才提交。

实际建模图不存在、不能解码、超字节／像素／格式规格、输入已过期、四图版本／摘要不符、供应商无多图能力仍给出具体错误。用户停止意图始终优先，取消质量门禁不能触发已停止任务自动3D。

旧被拦任务不再增加“继续原job”的专用恢复入口。用户重新生成时按最新规则新建；当前新任务2D就绪后不能因质量报告为false额外重做2D。

### 3.6 YOYOClaw错误详情透传

1. `yoyoclaw_client.py::wait_3d`从失败task提取实际`error.code/message`，复用脱敏／安全错误处理。公共归一化`code=provider_task_failed`保持，新增／透传可选`provider_code`与`provider_message`。
2. 沿Client→ProviderGateway→attempt→public job→`AIModelGenerationClient`→状态文案传递；原terminal、task绑定、retryable和ambiguous语义保持。不能用供应商具体code替换公共终态code，造成误判后重复生成。
3. 示例：“YOYOClaw生成几何失败：输入图片生成几何失败，请更换图片或重试。错误码：FailedOperation.InnerError。”只有明确额度／余额错误提示积分不足；认证失败、限流、超时和推理错误分别说明。
4. 错误码沿现有1～100个安全字符约束，界面说明最多512字符，过滤控制字符及敏感信息；缺字段、类型错误、未知码使用稳定中文兜底。
5. 可选字段兼容旧记录；旧失败可以只读显示或查询详情，不恢复生成、不为补错误自动重试。供应商不再提供的信息保留未知，不虚构根因或退款结论。

实施落地补充：既有历史侧栏增加“失败记录”，后台只读扫描本地智能／高级失败job，经既有客户端验证和脱敏后显示已保存的错误、任务和诊断引用。此入口不请求供应商、不改任务、不替换草稿或当前模型；旧记录没有保存详情时明确说明“无法据此判断是否积分不足”。真实远端旧task只读查询另行取证，不把查询结果写回原件。
