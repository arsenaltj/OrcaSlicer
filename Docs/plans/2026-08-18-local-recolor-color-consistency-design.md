# 局部改色颜色一致性修复设计

## 问题

局部选区当前始终使用固定蓝绿色不透明覆盖层。用户选择原绿色区域时，模型会立即显示成接近蓝色的青色；即使 OBJ 实际按目标颜色正确写入，应用后的选区计数又没有及时清零，界面仍像是保留着蓝色改色结果。

正式复现已经确认颜色数据链路没有交换通道：选择 `耗材 2 · #00FF00` 后，元数据记录 `recolor_target=#00FF00`，OBJ 顶点写入 `0.000000 1.000000 0.000000 1.000000`，重新加载后的模型显示绿色。

## 方案

1. 选区覆盖层不再固定使用青色，而是预览当前选择的目标耗材色。
2. 用户切换目标耗材颜色时，现有选区立即更新预览色，不需要重新点模型。
3. 模型加载或应用改色完成后，统一通知 UI 当前选区为零，清除旧计数并禁用“应用改色”。
4. 提示文案明确“模型上的高亮是改色预览，应用后写入新 OBJ”。
5. 增加红、绿、蓝三种非对称颜色的 OBJ 写出与 Orca 解析往返测试，防止以后出现真实 RGB/BGR 通道回归。

## 边界

- 不改变 OBJ 标准 RGB 顺序。
- 不改变选区算法、网格拓扑或导入切片逻辑。
- 不调用 Image2 或 Tripo。

## 验收

- 选择绿色时，选区预览立即为绿色。
- 点击应用后选区计数归零，高亮消失，模型保持绿色。
- 红、绿、蓝写出后经 `load_obj` 读取仍分别对应原通道。
