# 模型生成用户旅程精简设计

## 目标与方案

本轮不重构生成流程，而是在现有四步状态机上做渐进披露。比较过三个方案：删除专家能力、拆成多页向导、保留单页并按需展开。选择第三种，因为它能把普通用户的决策压缩到“生成图片 → 确认图片生成 3D → 导入/切片”，同时不破坏内部用户已经依赖的四阶段预览、结构复查、AI 视觉复核和局部改色。底部操作区继续作为唯一主操作位置，页面正文不再重复主要 CTA。

图片确认默认展示原始参考与“适合打印”结果。四阶段选择器和技术指标收进“查看处理过程”，展开后仍保持原有实时切换和详情。3D 结果默认展示模型、一个清晰质量结论和最多两条主要风险；结构指标、薄壁/悬垂复查、AI 视觉复核、优化与局部改色统一收进“高级检查与编辑”。加载、错误和恢复状态继续由现有状态机驱动，折叠状态不改变任务数据。

为 Beta 诊断增加本地 JSONL 旅程事件。Sidecar 只接受固定事件名及白名单字段，时间戳由本地服务生成；禁止额外字段，尤其是提示词、图片、路径和自由文本。事件覆盖图片请求/完成/重做/确认、3D 提交/完成/失败、导入、切片请求和打印反馈。记录失败不得阻断主流程。测试包括事件白名单与隐私拒绝、既有 Sidecar 全回归、C++ Release 构建，以及正式页面对默认折叠、键盘可达和单主操作的视觉检查。
