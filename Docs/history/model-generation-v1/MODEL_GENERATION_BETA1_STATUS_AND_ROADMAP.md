# 模型生成 Beta 1：当前状态与路线图

更新日期：2026-08-26

## 产品目标

第一阶段不承诺“任意输入都能一键生成完美模型”，而聚焦一个可以稳定兑现的核心场景：

> 文字或单主体图片 → 单色雕塑 / 多色写实 / 多色卡通 / 自定义风格参考图 → 单色或最多四种实际耗材色 → 3D 模型 → OrcaSlicer 导入与切片。

“快速”指减少用户决策和付费重试，不只指接口响应时间；“高质量”同时包含图像语义、3D 几何、可打印拓扑和真实打印效果。

| 打印风格 | 已收敛 | 单色雕塑、多色写实、多色卡通、自定义四种；固定风格均强调主体一对一保留 | 自动指标仍不能判断身份是否完全相似 |

| 图片质量门禁 | 已完成第二版 | 上传和供应商输出均完整解码；检查格式、大小、分辨率、透明/空白图、主体面积、连通性、色区和小区域 | 自动指标不能判断身份是否相似 |

## 当前验证基线

- 8 类高差异图片输入，两轮定向调优，共 35 次 Image2 调用。
- 八次正式 Tripo 生成：两次 50 万面调优样本、四次 30 万面单视图盲测和两次 30 万面多视图对照。
- 人像：239,148 顶点、478,292 三角面、1 个连通部件、0 非法拓扑边。
- 机器人：467,634 三角面、3 个保留部件、0 非法拓扑边。
- 人像和机器人均在正式 Orca 中完成多色导入和 500 层切片。
- 第一批 4 个未知文字输入均生成严格四色 OBJ：3 个结构 `pass`，1 个微小组件 `review`，0 个拓扑硬错误。
- 四例 AI 视觉与人工结论均为 `review`，精确一致率 4/4；证明复核有用，但也暴露单视图背面一致性缺口。
- Python AI 回归测试：阶段 50 最终回归见第五批实施结果。
- 2026-08-26 稳定性回归：289 个 Python 测试通过；四种图片风格与文字/图片/多色主路径各重复三轮，并验证无效建模参考图不会进入付费 3D 调用。
- Windows Release GUI 已用本地 Mock 遍历配色推荐、图片确认和自定义风格入口；主要操作按钮固定在页面底部，不随内容滚动消失。

这些证据足以支持演示和内部试用，但不足以证明对未知输入的稳定性，也没有证明真实打印颜色和结构质量。

## 是否能达成产品目标

方向正确，且限定场景下具备可行性。先生成可打印参考图、再确认后付费生成 3D，能明显减少风格和颜色错误造成的昂贵重试；动态耗材色与确定性 OBJ 后处理能降低进入 Orca 后的颜色意外；不可变制品与 Orca adapter 能降低上游版本演进带来的改造成本。

当前成熟度为：演示版已达到，内部试用基本达到，限定场景 Beta 已具备第一版 3D 结构门禁、建议式多视角视觉复核和 4 例盲测校准批，但仍缺 50–100 例正式盲测与真实打印验证。不能把“拓扑合法”直接等价为“模型高质量”：本批机器人和相机都证明单视图背面语义仍可能偏离。

## Beta 1 优先级

### P0：产品闭环

1. 建立结构化 3D 质量门禁，先覆盖拓扑、组件、接地、比例、悬垂和微小结构风险。
2. 增加统一角度渲染与视觉质量评分，识别身份、肢体和语义错误。
3. 建立 50 至 100 个未参与调优的盲测输入，并保留人工评分。
4. 完成 10 至 20 个真实打印，校准实际耗材颜色、换色成本、支撑和强度。
5. 将普通用户标准流程收敛为“输入、确认图片、确认模型”三次决策。

### P1：工程化

1. 抽取 `ModelGenerationCoordinator` 状态机、模型任务仓储和供应商 Gateway。
2. 将 `ModelGenerationPanel` 收缩为展示层；将 Sidecar 拆为 API、任务、供应商、图像、模型和存储模块。
3. 补齐安装、启动、诊断、日志、费用、取消和产物保留策略。
4. 整理当前未提交改动和滞后规划状态，形成可审核的 Beta 1 基线提交。

## 建议验收指标

以下是 Beta 1 的建议目标，不是当前已测结果：

- 50 个盲测输入全部产生可追踪报告。
- 图片首次认可率不低于 80%。
- 3D 首次可用率不低于 70%，一次用户明确确认的重试内不低于 90%。
- 进入 Orca 的模型 100% 通过确定性拓扑硬门禁。
- 四色模型正确导入/匹配率不低于 90%。
- 标准路径只要求三次主要用户决策。
- 至少 10 个真实打印中，8 个达到预先定义的外观与结构要求。

## 下一实施阶段

首先实现不依赖付费服务的 3D 结构质量门禁：输出 `model-quality.json`，将结果分为 `pass`、`review`、`reject`。第一版只对确定性错误做阻断，对底座、悬垂和微小部件等启发式风险只提示复核；后续再接入多视角渲染和视觉语义评分。

### 2026-08-16 第一批实施结果

- 已新增独立 `printable_model_quality.py`，不依赖 HTTP、Tripo 或 Orca GUI。
- 新生成 OBJ 在后处理完成后写入 `model-quality.json`，任务接口返回同一份报告。
- 默认严格拒绝非法拓扑；Sidecar 明确声明下游 Orca 修复能力时，修复上限内的小缺陷降为 `review`，超限仍拒绝。
- 阶段 45 人像结果为 `pass`；机器人结果为 `review`，唯一提示是两个极小脱离组件，两个模型都没有被错误拒绝。
- 合成网格覆盖 pass、review、reject；AI Python 全量回归 135/135 通过。
- 当前第一版只在新制品后处理时生成报告。旧任务没有报告时仍可恢复并返回空 `model_quality`，不会在 Sidecar 启动时同步扫描全部历史大模型；历史制品的显式重验入口留给下一批实现。

### 2026-08-16 第二批实施结果

- 3D 预览已增加常驻中文质量卡，完整呈现 `pass / review / reject`；`review` 允许用户确认后导入，`reject` 强制禁用导入。
- 已增加本地历史重验接口和“重新检查”操作，不调用 Image2、Tripo 或 conversion；检查期间保留模型预览并暂时禁用导入。
- 早期没有 `job.json` 的模型可按 UUID 与固定 `model-vertex-color.obj` 安全接管，不接受客户端文件路径，也不允许访问任务目录外文件。
- 正式 Orca 已用现有真实历史模型完成三态验收：通过模型、可修复/微小组件复核模型、退化三角面阻断模型均符合预期。
- 历史模型库遇到残缺条目不再提前终止扫描；但 GUI 与 Sidecar 必须由启动脚本显式共享 `ORCASLICER_AI_OUTPUT_DIR`，不能依赖会变化的当前目录。
- Windows Release 构建与部署通过，AI Python 全量回归 138/138；本批没有新增付费 AI 调用。

### 2026-08-16 第三批实施结果

- 最终顶点色 OBJ 已能生成前、后、左、右、等轴五视图和拼图，产物与 SHA-256 缓存清单保存在任务目录。
- 用户显式点击后才调用视觉模型；图生 3D 同时对照原参考图，文生 3D 对照文字描述。失败返回 `unavailable`，不会改变模型 ready 状态。
- 视觉报告固定为 `pass / review / unavailable`，第一版不产生硬拒绝；结构 `reject` 仍是唯一自动阻断导入的 3D 质量结论。
- 正式人物模型完成一次真实复核：86 分、置信度 0.91，准确指出半身收尾缺少独立底座；GUI 显示中文解释且仍允许导入。
- 29.6 万面模型首次五视图约 12.8 秒；AI Python 回归 148/148，Windows Release 完整构建和正式 GUI 验收通过。

下一步先验证多视图 3D 输入对背面/侧面一致性的改善；通过 20 个校准样本后，再扩到 50–100 个未参与提示调优的正式盲测，并选择 10–20 个代表模型真实打印，校准耗材颜色、底座、支撑、薄壁和换色成本。

### 2026-08-16 第四批实施结果

- 新增清单驱动的可恢复盲测编排器，所有付费阶段均需显式确认；Image2、Tripo 和视觉调用都先记账再执行，失败不会自动重复付费。
- 用 4 个从未参与调优的文字任务完成动态四色参考图、Tripo 30 万面生成、OBJ 转换、顶点色后处理、结构门禁、五视图、视觉复核和人工 7 维评分。
- 四个参考图均通过本地四色质量门槛；四个 OBJ 均只有目标四种顶点色，且边界边、非流形边和退化面全部为 0。
- 狐狸、机器人和相机结构 `pass`；塔楼因 5 个仅 4 顶点的微小脱离组件为 `review`。
- 视觉模型与人工结论 4/4 精确一致，均为 `review`。背面/侧面语义成为当前首要质量缺口，不再是颜色或拓扑链路。
- 本批实际调用为 4 次 Image2、4 次 Tripo 生成、4 次转换和 4 次视觉复核，没有重复任务。
- 完整报告见 `Docs/MODEL_GENERATION_BLIND_PILOT_V1_REPORT.md`。下一批先验证多视图 3D 约束，再扩正式盲测样本量。

### 2026-08-16 第五批实施结果

- 新增固定 2×2 正交转台四视图、确定性切分、逐视图严格四色、AI 一致性预检、人工批准审计和 Tripo v3 命名多视图编排。
- 机器人多视图模型为 282,616 面、单连通主体、零边界/非流形/退化面，视觉分数由单视图基线 78 提升到 88；原先背面异常遮挡和侧面细长伪影消失。
- 相机多视图模型为 279,578 面、零边界/非流形/退化面，视觉分数由 71 提升到 82；结构仅因一个 4 顶点微小组件为 `review`，主体和四色均完整。
- 两例均严格使用目标四种顶点色，无越界颜色；实际新增 4 次 Image2、2 次 Tripo 生成、2 次转换、6 次生成前视觉复核和 2 次最终模型视觉复核。
- 没有启用第三个 Tripo 样本。多视图在 2/2 对照中均提升 10 分以上，方向成立，但样本不足以直接产品化。
- 架构复核确认本阶段没有向 Orca GUI、3MF 或打印配置扩散供应商字段；纯多视图模块已移除默认 OpenAI 客户端依赖。正式接入前仍需抽取 Sidecar `ModelGenerationGateway`。
- 最终 AI Python 全量回归 169/169、34 个 AI 脚本语法检查和 `git diff --check` 通过；本阶段没有 C++ 或 3MF 契约改动，因此未重复构建 Orca。
- 详细架构结论见 `Docs/architecture/2026-08-16-phase50-multiview-review.md`。

### 2026-08-16 第六批实施结果

- 把最终 OBJ 的结构、五视图视觉和同源单图基线比较做成可恢复 `review` 阶段；重复执行可命中缓存，不会隐式产生付费调用。
- 狐狸多视图模型为 288,836 面、严格四色且零非法拓扑，自动视觉由 82 提到 83；人工检查发现头顶悬浮圆环/横线，最终判定拒绝。
- 塔楼在 3 次 Image2 内无法稳定保持三层离散结构，生成前拒绝，因此没有消耗 Tripo 3D。
- 累计 4 组单图/多视图配对只有机器人和相机被人工接受，固定四宫格路线的接受率为 2/4，证据不足以进入正式产品链路。
- 新增人工拒绝审计和硬阻断，避免自动视觉高分或人工批准参数覆盖明确失败；第二批只新增 1 次 Tripo 生成和 1 次转换。
- 架构方向调整为供应商无关的 `single_image / generated_turntable / provider_multiview / user_supplied_views` 策略路由；在完成 Gateway 抽取与下一批 6 例校准前，ADR 保持 Proposed。
- 最终 AI Python 全量回归 175/175、34 个脚本语法检查和差异格式检查通过；本批没有 C++/3MF 修改，因此未重复构建 Orca。
- 完整报告见 `Docs/MULTIVIEW_CALIBRATION_WAVE2_REPORT.md`，架构复核见 `Docs/architecture/2026-08-16-phase51-calibration-review.md`。
